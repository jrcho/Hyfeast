    14. Step Result

    해석된 결과를 관리하는 명령으로 *PostStep, *History, *PostHistory, *HDB 등이 있다.

    14.1 *History

    대상 step을 대상으로 해석을 수행 중 이력(history) 결과를 출력한다.

    *History, Name=name
 step1, step2, ...
 sensorName|scalarField[:orientation]@target, ...
 ...
    Keyword line
    • Name=name: *History 및 *PostHistory 명령에서 생성하는 명칭. 중복될 수 없음. 이 이름으로 name.csv 파일이 생성됨. 이름에 이 포함되는 경우 현재의 DB 이름(입력파일에서 확장자를 뺀 이름)으로 파일 이름이 생성됨.
    First dataline
    • step1, step2, ...: 대상 해석 스텝
    Second dataline and subsequent datalines
    • sensorName: 출력한 센서 명칭

    • scalarField[:orientation]@target: 스칼라 필드 명칭과 대상. scalarField는 하위 성분을 갖는 필드는 D.X, FN.Y, SF.X, SE.X, S.11, E.33 등의 형태이고, PEEQ 같은 스칼라 필드는 그대로 적용. orientation은 선택 항목이며 *CoordinateSystem, Type=Orientation의 명칭 또는 GCS를 지정한다. target은 절점, 요소 필드에 따라 아래와 같이 형식이 결정됨.

      • scalarField@nodes: 절점필드
      • scalarField@elements-gpIndices: 요소 적분점에 정의된 요소 필드
      • scalarField@elements-gpIndices-cellId: 요소 적분점내의 셀에서 정의된 요소 필드
      • scalarField@elements-gpIndices-cellId-pointId: 요소 적분점-셀-포인트에서 정의된 요소 필드
      • Details
        • nodes: 절점번호,절점번호패턴(start:end:spacing, start:end 형태), 절점집합 등으로 지정하는 대상 절점
        • elements: 요소번호,요소번호패턴(start:end:spacing, start:end 형태), 요소집합 등으로 지정하는 대상 요소
        • gpIndices: 적분점인덱스, 적분점인덱스 패턴(start:end:spacing, start:end 형태) 등으로 지정하는 대상 적분점인덱스들. 적분점인덱스는 1-based이고, last는 최종 적분점인덱스를 의미
        • cellId: 적분점내의 셀 번호. Beam/Interface/Spring 요소 등에서 다른 재료로 정의되는 계층을 의미. 예외적으로 Shell 요소에서는 셀번호 대신 homogeneous 단면의 경우 B(하단), T(상단), 적층쉘의 경우 LayerId 사용
        • pointId: 셀내의 재료점 번호. Meshed Cell이나 Layered Cell을 갖는 단면을 가지는 Beam 요소에서 셀 내의 재료점의 의미

    *History 명령은 절점의 성분이나, 요소 단위 필드의 개별 성분을 시간에 따른 히스토리 파일로 저장한다. sensor인 경우 센서에서 정의한 스칼라 값이 사용된다. scalarField@target의 경우 스칼라 필드 명칭과 드불어 대상 위치를 지정해야 한다. scalarField는 절점 필드와 요소 필드로 구분된다.

    orientation을 지정하면 벡터 또는 텐서를 먼저 해당 orientation 좌표계로 변환한 뒤 요청한 성분을 추출한다. CSV heading에는 scalarField:orientation@target 형태가 유지되므로 전역좌표계 성분과 orientation 좌표계 성분을 같은 파일에 함께 출력해도 구분할 수 있다.

    orientation을 붙일 수 있는 결과는 다음으로 제한된다.

    • 절점 벡터 성분: D, V, A, FN, FE, FK, FC, FM의 X, Y, Z, RX, RY, RZ
    • 연속체 요소 텐서 성분: S, E, EM, EE, EP, ENM, ETH, SB의 11, 22, 33, 12, 23, 31
    • 침투해석 연속체 요소 벡터 성분: GRADP, GRADH, FLX의 X, Y, Z

    보/쉘/스프링/인터페이스의 고유 국부 결과(BSF, BSE, BST, SSF, SSE, SST, SF, SE, DF, DE, ITR, IRD 등), 스칼라 결과, 벡터 크기(Mag), 텐서의 주값/불변량(P1, P2, P3, Mises)에는 orientation을 붙일 수 없다. 2D 연속체 요소 결과는 면내 orientation만 지원한다.

    절점 필드의 경우
    1. field.sub[:orientation]@nodes 형태로 지정한다.

    2. nodes는 절점번호,절점번호패턴(start:end:spacing, start:end 형태), 절점집합 등으로 지정하는 대상 절점이고. 이때 절점번호에는 정수 또는 괄호로 묶은 expression을 사용할 수 있다.

    3. field로는 D, V, A, FN, FE, FK, FC, FM이 가능하다.

      • D : Displacement, D = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • V : Velocity, V = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • A : Acceleration, A = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • FN : Externally applied nodal force (external force), FN = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • FE : Equivalent nodal force (external force), FE = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • FK : Restoring force (internal force), FK = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • FC : Damping force (internal force), FC = [X, Y, Z, RX, RY, RZ, P, T, Mag]
      • FM : Internal force (internal force), FM = [X, Y, Z, RX, RY, RZ, P, T, Mag]
    4. sub에는 X, Y, Z, RX, RY, RZ, P, T, Mag 등의 자유도와 이들로부터 계산된 값을 의미하는 문자가 올 수 있다. 그 의미는 다음과 같다.
    5. X,Y,Z` : X, Y, Z 방향 병진 자유도
    6. RX, RY, RZ : RX, RY, RZ` 방향 회전 자유도
    7. P : Pressure 자유도( Acoustic element only )
    8. T : 온도 자유도( reserved )
    9. Mag : X, Y, Z 자유도의 크기

    예

    • D.X@1 : 1번 절점의 X displacement
    • D.X:inc@1 : 1번 절점 displacement를 inc orientation으로 변환한 뒤 X 성분
    • D.X@2:8:2 : 2,4,6,8번 절점의 X displacement
    • D.P@2:5 : 2,3,4,5번 절점의 P
    • D.Mag@10 : 10번 절점의 X,Y,Z 자유도의 크기 (벡터의 크기로 계산)
    • FN.RX@slab : slab 절점 집합의 RX 방향 external nodal force
    • D.X@2+5 : D.X@7을 의미
    • D.X@3*(4-1) : D.X@9를 의미
    • D.Z@1+2:9:3 : D.Z@3:9:3을 의미
    요소 필드의 경우
    1. scalarField[:orientation]@target에서 scalarField는 하위 성분이 존재하는 경우에는 field.sub, 하위 성분이 없는 field 형태이다.

    2. 다음은 적용가능한 필드의 명칭과 그 하위 성분을 나열한 것이다.

      • BSF = [Nx My Mz Vy Vz T] , beam section forces
      • BSE = [Ex Ky Kz Gxy Gxz Hx] , beam section deformation
      • BST = [T0 Ty Tz] , beam section temperature
      • SSF = [Nx Ny Nxy Mx My Mxy Vx Vy] , shell section forces
      • SSE = [Ex Ey Gxy Kx Ky Kxy Gxz Gyz], shell section deformation
      • SST = [T0 Tz] , shell section temperature
      • SF = [X Y Z RX RY RZ] , spring forces
      • SE = [X Y Z RX RY RZ] , spring deformation
      • DF = [X Y Z RX RY RZ] , damping forces
      • DE = [X Y Z RX RY RZ] , damping deformation rate
      • S = [11 22 33 12 23 31 P1 P2 P3 Mises], stress
      • E = [11 22 33 12 23 31 P1 P2 P3], total strain
      • EM = [11 22 33 12 23 31 P1 P2 P3], mechanical strain
      • EE = [11 22 33 12 23 31 P1 P2 P3], elastic strain
      • EP = [11 22 33 12 23 31 P1 P2 P3], plastic strain
      • ENM = [11 22 33 12 23 31 P1 P2 P3], non-mechanical strain
      • ETH = [11 22 33 12 23 31 P1 P2 P3], thermal strain
      • SB = [11 22 33 12 23 31 P1 P2 P3], back stress
      • PEEQ , Equivalent plastic strain
      • PEEQT, Tensile equivalent plastic strain
      • PEEQC, Compressive equivalent plastic strain
      • MTEMP, Material temperature
      • ECUN , Last compressive loading strain from origin of UGeneric material
      • ETUN , Last tensile loading strain from origin of UGeneric material
      • ITR = [A B N], interfacial traction
      • IRD = [A B N], interfacial relative displacement
      • ELTIME, Element elapsed physical time after activation
      • ECR , Creep strain
      • ESH , Shrinkage strain
      • EAG , Aging strain
      • PEL , Element pressure
      • VOL , Element volumetric strain
      • SPF , Stiffness proportional factor in ModelUpdating
      • MPF , Mass proportional factor in ModelUpdating

    3. scalarField[:orientation]@target을 풀어쓰면 다음과 같고 target으로는 elements-gpIndices. elements-gpIndices-cellId, elements-gpIndices-cellId-pointId이 될수 있다. ELTIME은 요소 활성화 이후 경과한 물리 시간이며 요소 단위 derived field이다. *History에서는 일반 요소 필드와 같은 ELTIME@elements-gpIndices 형식만 사용한다. 예를 들어 ELTIME@10-1, ELTIME@10-last, ELTIME@elset1-1은 가능하지만, 적분점 인덱스가 없는 ELTIME@10이나 ELTIME@elset1은 사용하지 않는다.

    4. elements에는 요소번호,요소번호패턴(start:end:spacing, start:end 형태), 요소집합 등으로 지정하는 대상 절점이고. 이때 절점번호에는 정수 또는 괄호로 묶은 expression을 사용할 수 있다. gpIndices는 적분점인덱스 패턴(start:end:spacing, start:end 형태) 등으로 지정하는 대상 적분점인덱스들. 적분점인덱스는 1-based이고, last는 최종 적분점인덱스를 의미한다. gpIndices 역시 괄호로 묶은 expression을 사용할 수 있다. elements와 gpIndices에 expression을 사용할 때 - 연산자는 계층 구분자와 혼동될 수 있으므로 적절하게 괄호를 사용해야 한다.

    5. 연속체 요소에서의 형식과 예는 다음과 같다.

      • scalarField@elements-gpIndices
      • examples
        • S.12@3-1 : 3번 요소, 1번 적분점에서 S.12
        • S.11:inc@3-1 : 3번 요소, 1번 적분점의 응력 텐서를 inc orientation으로 변환한 뒤 11 성분
        • S.Mises@5-1:3 : 5번 요소, 1,2,3 적분점에서 S.Mises
        • PEEQ@beam-1:last : beam 요소 집합내 요소, 모든 적분점(1:last)의 PEEQ

    6. 보 요소에서의 형식과 예는 다음과 같다.

      • scalarField@elements-gpIndices : 요소 적분점에 정의된 요소 필드
      • scalarField@elements-gpIndices-cellId-pointId : 요소 적분점-셀-포인트에서 정의된 요소 필드
      • examples
        • BSF.My@3-1 : slab 요소 집합내의 요소들, 1번 적분점의 BSF.My
        • BSF.My@3:5-1 : 3번, 5번 요소 1번 적분점의 BSF.My
        • BSF.Nx@slab-1 : slab 요소 집합내의 요소들, 1번 적분점의 BSF.Nx
        • S.11@1-1-2-10 : 보요소, 1번 요소, 1번 적분점, 2번 Cell의 pointId 10에서의 S.11
        • EM.11@2-2-1-3 : 보요소, 2번 요소, 2번 적분점, 1번 Cell의 pointId 3에서의 EM.11
        • BSF.Nx@10-1 : element 10, 1번 적분점의 BSF.Nx
        • BSF.Nx@(2+3)-1 : element 5, 1번 적분점의 BSF.Nx
        • BSF.Nx@(3*(4-1)+1)-2 : element 10, 2번 적분점의 BSF.Nx (괄호 필수)
        • BSF.Nx@(5-2)-1 : element 3, 1번 적분점의 BSF.Nx (괄호 필수)

    7. Spring, Interface 요소의 형식과 예는 다음과 같다. Spring은 gpIndex가 항상 1이다.

      • scalarField@elements-gpIndices : 요소 적분점에 정의된 요소 필드
      • scalarField@elements-gpIndices-cellId : 요소 적분점내의 셀에서 정의된 요소 필드
      • examples
        • SF.X@3-1 : 3번 요소, 첫 번째 적분점의
        • scalarField@elements-gpIndices-cellId : 요소 적분점내의 셀에서 정의된 요소 필드

        • SF.X@1-1 : Spring 요소, 1번 요소, 1번 gp(항상 1번), SF.X
        • EM.11@1-1-1 : Spring 요소, 1번 요소, 1번 gp(항상 1번), 1번 cell의 EM.11
        • ISD.11@1-1-1 : Spring 요소, 1번 요소, 1번 gp(항상 1번), 1번 cell의 EM.11
        • IRD.A@1-2 : Interface 요소, 1번 요소, 2번 gp, IRD.A

    8. Shell 요소의 형식과 예는 다음과 같다.

      • scalarField@elements-gpIndices : 요소 적분점에 정의된 요소 필드

      • examples

        • EM.12@11-3-2 : 쉘요소, 11번 요소, 3번 적분점, 2번 layer의 EM.12 기계 변형률 (Composite 단면)
        • PEEQ@101-4-B : 쉘요소, 101번 요소, 4번 적분점, 하단에서의 PEEQ

    14.2 *PostHistory

    해석이 끝나(.hdb 파일이 생성된 후) 대상 step을 대상으로 이력(history) 결과를 구하여 출력한다.

    *PostHistory, Name=name
 step1, step2, ...
 scalarField[:orientation]@target|sensorName, ...
 ...

    명령의 양식은 명령어 명칭을 제외하고 *History와 동일함.

    *History는 해석을 수행하면서 이력 데이터를 구하고, *PostHistory는 해석이 끝난후 *Output으로 지정한 데이터에서 이력데이터를 구한다. 따라서 *History는 *Output에서 지정한 필드가 아니더라도 그 해석 모델에 존재하는 데이터에 대한 이력 데이터를 얻을 수 있지만, *PostHistory는 그렇지 않다.

    *PostHistory에서 orientation을 사용하는 경우에는 변환 전의 기본 필드가 HDB에 저장되어 있어야 한다. 예를 들어 D.X:inc@10은 *Output에 D가 있어야 하고, S.11:inc@solidSet-1은 *Output에 S가 있어야 한다. HDB에 이미 추출된 스칼라 결과만 있는 경우에는 orientation 변환을 수행할 수 없다.

    14.3 *PostStep

    해석 결과를 이용해 새로운 해석 스텝 결과를 조합한다.

    *PostStep, OrphanHDB=On|Off, Name=name
 targetElset, ...
 targetField, ...
 [label =] frameExpression, C=...
 ...
    Keyword line
    • Name=name: 해석의 이름
    • OrphanHDB=On|Off: PostStep의 결과에 대응하는 ResultStep 만을 갖는 별도의 .hdb 파일을 생성할지를 지정. default는 Off. On이면 name.hdb 등과 같은 *PostStep의 명칭과 같은 이름의 .hdb 파일에 대응하는 ResultStep만을 저장하여 생성해줌.
    First dataline
    • targetElset: 대상이 되는 요소집합
    Second dataline
    • targetField: SF, S, D 등과 같이 대상이 되는 필드 또는 센서.
    Third dataline and subsequent lines
    • frameExpression: 생성할 프레임의 규칙. L1.MAX, 0.8*L1.MAX+0.8*L2.MIN, DC.2 등
    • label: 생성되는 frame의 이름. 공백 등이 필요한 경우 "..."로 감싼다.
    • C=...: frameExpression에 MIN, MAX가 존재하는 경우 targetField의 최대,최소 조건. 지정하지 않는 경우 개별 필드의 최대 최소가 계산됨

    생성할 프레임 규칙은 factor step.frame 형태의 선형조합으로 작성한다. factor는 숫자이고, step은 사용한 ResultStep 이름이다. factor가 1인 경우에는 factor는 생략가능하다. frame은 프레임 넘버(1-based) 또는 min, max, last 등이 올 수 있다. min은 전체 프레임을 대상으로 최소값을 의미하고, max는 최대값을 의미한다. last는 마지막 프레임을 의미한다. ResultStep 이름인 step은 대소문자를 구분하나, min, max, last는 대소문자 구분을 하지 않는다.

    각 프레임 규칙은 label = frameExpression 형식으로 이름을 지정할 수 있다. 이름을 지정하지 않은 기존 형식도 허용된다. HDB frame metadata 규칙은 18.8 *Frame에서 일괄 정리한다.

    - `1.2*DC.1 + 1.8*DL.1`: Result of adding 1.2 times the first frame of the DC step and 1.8 times the first frame of the DL step.
- `1.2*L1.max`: Result of finding the maximum value across all frames in the L1 step and multiplying it by 1.2.
- `DC.2 + EQ.max`: Sum of the second frame value in the DC step and the maximum value in the EQ step.
- `DC.last + DW.last`: Sum of the last frame values in the DC and DW steps.

    *PostStep은 *Step 명령 수행 후 .hdb 파일내에 생성되는 ResultStep을 대상으로 결과값의 조작하게 된다. 따라서 *Step 명령 이후에 존재해야 한다.

    Example
    # Dead load case
*Step, Type=Static, Name=DC
 ...

# Live Load : Lane 1
*Step, Type=Static, Quasi, Name=L1
 Uniform, 1, 1, TUnit=s

# Live Load : Lane 2
*Step, Type=Static, Quasi, Name=L2
 Uniform, 1, 1, TUnit=s

# Earthquake
*Step, Type=Dyanamic, Name=EQ
 ...


*PostStep, OrphanHDB=On,   Name=LL    # Generates LL.hdb or LL.text.hdb additionally.
 myslab1, myslab2          # target elements
 BSF, D                    #  target Field
 L1.MAX                    # frame 1
 L2.max                    # frame 2
 0.8*L1.MAX + 0.8*L2.MAX   # frame 3
 Lane1Min = L1.min         # frame 4
 Lane2Min = L2.MIN         # frame 5
 "LL Envelope Min" = 0.8*L1.MIN + 0.8*L2.MIN   # frame 6


*PostStep, Name=LimitState
 myslab1, myslab2          # target elements
 BSF, SSF, S, D       # target scalar fields
 ULS_BSF = 1.2*DC.2 + 1.8*LL.max, C=BSF.2, SSF.1
 ULS_Disp = 1.2*DC.2 + 1.8*LL.min, C=D.MAG
 DC.2 + LL.MAX + EQ.MAX
 DC.2 + LL.MIN + EQ.MIN

    14.4 *HDB

    .hdb 파일을 읽어온다.

    *HDB, File=hdbfile
    Keyword line
    • File=hdbfile: .hdb 파일 명칭

    *HDB 명령은 이미 해석을 수행하여 HDB 파일이 존재할 경우 *PostStep 등의 명령으로 .hdb 파일의 결과를 갱신하고자 할 때, .hdb 파일을 읽어오는 역할을 한다. *HDB 명령은 파일내에서 첫 번째 명령이고 한번만 사용할 수 있으며, 이후 다음의 명령을 통해 .hdb 파일을 수정할 수 있다.

    • *Nset : 새로운 절점집합 생성시에만 가능
    • *Elset: 새로운 요소집합 생성시에만 가능
    • *Info : 새로운 정보 생성시에만 가능
    • *PostStep
    • *PostHistory
    Example
    *HDB, File=bridge.text.hdb

 BSF, D                    #  target Field

 Lane1Min = L1.min         # frame 4
 Lane2Min = L2.MIN         # frame 5
