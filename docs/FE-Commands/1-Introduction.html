    1. 개요

    1.1 입력 파일과 command block 구조

    Hyfeast의 커맨드라인 해석기 hfAnalyzer는 텍스트 입력 파일을 읽어 해석을 수행한다. 입력 파일은 *Node, *Element처럼 *로 시작하는 예약 키워드 블록으로 이루어진다. 다음은 간단한 프레임 해석 입력 파일 예시다.

    # Portal Frame Example

*Node
 1, 0., 0.
 2, 0.,10.
 3,10.,10.
 4,10., 0.

*Element, Type=B2D2H, Elset=ALL
 1, 1, 2
 2, 2, 3
 3, 3, 4

*Material, Type=IsoElasticity, Name=beam
 210E9, 0.3, 0, 7700

*Section, Type=Beam, Name=BeamSection, Mass=Lumped
*Cell, Type=Rectangle, MAT=beam
 0.4, 0.1

*Distribution, Type=Section
 ALL, BeamSection

*Constraint, Type=Support, Name=BC
 1, X|Y|RZ
 4, X|Y|RZ

*Load, Type=Concentric, Name=LC2
 2, X, 100E3

*Step, Type=Static, Name=Case1
*Activate, Type=Element
 ALL
*Activate, Type=Constraint
 BC
*Activate, Type=Load
 LC2
*Output
 D, FN, BSF

    다음은 입력 텍스트 파일에서 사용되는 일반규칙을 나열한 것이다.

    • 한글과 같은 Non-Ascii 문자가 존재하는 경우 UTF-8로 인코딩되어야 한다.
    • 입력파일은 텍스트파일이며 한 줄씩 순차적으로 읽어 들여 파싱한다.
    • 공백라인은 무시하고, # 문자로 설명문(comment)을 작성할 수 있다.
    • 문자를 사용하여 다음 줄과 연결(concatenation)할 수 있다.
    • 예약된 키워드(keyword)는 대소문자를 구분하지 않으나, 사용자 정의 문자열(예: 요소집합 이름 등)은 대소문자를 구분한다.

    • 각 라인은 n1, n2, n3 또는 n1, ..., ID=id1, ... 등과 같은 형태를 가지는 프리포맷(free format)이다. 이때 파싱의 대상이 되는 토큰(token)은 등호(=), 쉼표(,)를 기준으로 구분된다. 프로그램 내부적으로 작동하는 방식은 다음과 같다.

      • 등호(=)를 찾아 등호의 왼쪽 키워드를 인식
      • 프리포맷(free format) 형태로 인식된 각각을 쉼표(,)를 구분자로 각 토큰으로 분할
      • 이중따옴표로 둘러싸인 경우 하나의 토큰으로 인식

    • 실수나 정수로 입력이 되는 부분은 간단한 산술 연산을 수행할 수 있다. 예를 들어 1+2*(10+2)와 같은 산술 연산을 수행한다. 연산식 내에 공백이 존재하는 경우 토큰으로 분리되므로 공백이 존재하면 안된다. 만약 공백이 존재하는 경우 하나의 토큰으로 인식하게 하려면 이중따옴표를 사용하여야 한다(예 “1 + 2*(10+2)”)

    • 산술식에서는 20*sin(30*deg) 등과 같이 다음에서 미리 정의된 함수, 상수 등을 사용할 수 있다.

      • f(x) 형태의 함수: sin, cos, tan, acos, atan, cosh, sinh, tanh, abs, exp, log, log10, sqrt, step, sgn
      • f(x,y) 형태의 함수: pow, max, min
      • Constant: pi, e, deg, g0 (g0는 표준중력가속도, \(9.80665\,\mathrm{m/s^2}\)). g0를 사용하려면 *Environment, TYPE=UnitSystem을 통해 global UnitSystem이 정의되어 있어야 한다.

    • 문자열이 입력되는 부분에서 공백이 있는 경우 이중따옴표로 묶어주어야 한다. 예를 들어 *Material, TYPE=IsoElasticity, Name="the material")

    • 파일명을 문자열로 입력받는 경우 상대경로, 절대경로를 모두 인식한다. 만약 경로상에 공백이 있는 경우 이중따옴표로 묶어주어야 한다. 상대경로는 입력파일이 존재하는 디렉토리를 기준으로 한다. 예를 들어 다음과 같다.
    *Include, File=model1.inp
*Include, File=templates/model1.inp
*Include, File="templates folder/model 1.inp" # if spaces exist, use double quotes
*Include, File="./templates/frame model.inp" # . means current directory
*Include, File="../frame model.inp" # .. means parent directory
*Include, File="D:/DevProg/HFC4.0/EXAMPLE/frame model.inp" # absolute path

    *로 시작하는 명령어(command)는 크게 모델링 명령, 해석 명령, 기타 명령로 구분할 수 있다. 다음은 명령어를 요약한 것이다.

    절점 명령
    • *Node
    • *Nset
    • *Ngen
    • *Nfill
    • *Ncopy
    • *Nprop
    요소 명령

    • *Elset
    • *Elgen
    • *Elcopy
    • *Section
    하중과 구속조건 명령

    • *Constraint
    프라퍼티 명령
    • *Material
    • *Function
    • *Surface
    • *Geometry
    • *CoordinateSystem
    해석 명령
    • *Step
    • *Activate
    • *Inactivate
    • *Convergence
    • *SolutionAlgorithm
    • *TimeIntegration
    • *RayleighDamping
    • *Modal
    • *State
    • *Output
    • *Print
    • *Check
    해석 결과 관리 명령

    • *History
    • *PostHistory
    • *HDB
    모델링 편의 명령

    1.2 해석 실행

    hfAnalyzer는 CLI(Command-Line Interface)에서 구동되는 프로그램이다. 명령행에 hfAnalyzer와 입력 파일을 타이핑하면 해석이 가능하다.

    CLI 셸은 실행 환경에 맞게 연다. 개발 트리에서는 저장소 루트의 cmdQt6.bat 또는 cmdQt5.bat를 실행해 빌드 출력 폴더와 개발 의존성 경로를 PATH에 추가한다. 배포판에서는 배포 루트의 setpath.bat를 실행한다. 이 배치파일은 자기 위치를 기준으로 Bin 폴더를 PATH에 추가한다.

    hfStudio와 hf2DStudio의 Open Hyfeast CLI Here 메뉴를 사용하면 현재 작업 파일이 있는 폴더에서 별도 cmd.exe 창이 열린다. 개발 실행에서는 cmdQt6.bat 또는 cmdQt5.bat로 환경을 잡고, 배포 실행에서는 실행 파일이 들어 있는 Bin 폴더를 직접 PATH에 추가한다. 이 메뉴는 현재 모델을 자동 저장하거나 export하지 않으며, Studio가 열고 있는 HDB 파일 핸들을 새 CLI 창에 상속하지 않는다.

    > hfAnalyzer frame.inp

    또한 HDB family 파일(.hdb, .text.hdb, .bin.hdb)도 해석 입력으로 사용할 수 있다. 이 경우 HDB 안에 저장된 입력/모델 스냅샷을 먼저 꺼내 해석하며, 기본값으로 원본 HDB는 덮어쓰지 않는다.

    > hfAnalyzer frame.hdb
> hfAnalyzer frame.text.hdb
> hfAnalyzer frame.bin.hdb

    -o 옵션은 출력 HDB 이름을 직접 지정할 때 사용한다. -o가 없으면 원본 이름을 기준으로 frame.rerun.hdb, frame.rerun.text.hdb, frame.rerun.bin.hdb처럼 rerun을 붙인 파일을 만든다. 원본 HDB를 해석 결과로 교체하려면 HDB 입력에서만 -r을 사용한다.

    > hfAnalyzer frame.hdb -o frame_cli
> hfAnalyzer frame.hdb -r

    명령행 실행시의 입력파일 외에 다양한 추가 옵션이 있는데 이는 -h 옵션으로 알 수 있다.

    > hfAnalyzer -h

    단순히 hfAnalyzer를 타이핑하여 실행하면 interactive하게 구동할 수 있다.

    > hfAnalyzer ... Input file 등 필요한 정보를 interactive하게 타이핑

    해석을 실행하면 다양한 결과 파일이 만들어진다. 예를 들어 입력파일이 frame.inp라고 가정하면(즉, > hfAnalyzer frame.inp 실행) 해석결과를 담고 있는 hdb 파일 생성한다. hdb 파일은 hfVisualizer 전용파일로서,

    • hfVisualizer를 프리프로세싱 모드에서는 해석결과가 없이 입력파일 정보만 담고 있지만
    • 포스트포로세싱 모드에서는 입력파일 정보와 더불어 해석결과를 담고 있다.

    hdb 파일은 hdf5(디폴트이고 확장자를 .hdb), text(확장자는 .text.hdb), binary(확장자는 .bin.hdb)의 세가지 형식으로 생성할 수 있다. 다음은 각각에서 생성되는 파일을 정리한 것이다.

    ■ hdf5 인 경우 (> hfAnalyzer frame.inp)

    frame.hdb
frame.log
frame.chk
frame-step1.rst
frame-step2.rst
...

    ■ text 인 경우 (> hfAnalyzer frame.inp -f text)

    frame.text.hdb
frame.text.hdb.info
frame.text.hdb.inp
frame.log
frame.chk
frame-step1.rst
frame-step2.rst
...

    ■ binary 인 경우 (> hfAnalyzer frame.inp -f binary)

    frame.bin.hdb
frame.log
frame.chk
frame-step1.rst
frame-step2.rst
...

    1.3. 파라미터 입력 제어

    1.3.1. 기본사용법

    hfAnalyzer를 명령행에서 실행할 때 -p 옵션을 통해 파라미터 입력을 제어할 수 있다. 입력파일은 이 -p 옵션에서 주어지는 표현을 사용하여 미리 작성되어 있으면 된다.

    example.inp 

    ...
*Material. Type=IsoElasticity, Name=concrete
 <E>, 0.18

*Node, Offset=<BaseN>
 1, 10, 0, 1
...

    일 때

    > hfAnalyzer example.inp -p "<E>=20E9, <BaseN>=1000"

    을 실행하면 입력파일에서 <E>와 <BaseN>이 주어진 값으로 치환되고, 출력 파일의 기본 이름(base name)도 example-20E9-1000으로 설정된다(출력 파일이 example-20E9-1000.hdb, example-20E9-1000.log 등). -p 이후의 표현식은 "key=value, ..." 형태이고 ""로 둘러싸여야 하며, 입력 파일에서 key는 value로 치환되게 된다. 이때 key는 다른 문자열과 구분되어야 하기 때문에 <A>, $A$ 등과 같이 일반적으로 잘 사용하지 않는 기호로 둘러싸는 것이 좋다. 예를 들어 예를 들어 "<E>=20E9, <B>=7.3" 와 같이 쓰면 <K>는 20E9로, <B>는 7.3으로 치환하게 된다. 한편 파라미터 표현식내부에서 토큰은 {}로 묶을 수 있다. 예를 들어 "<K>={R,12.3}, <B>=7.3" 등과 같이 쓰면 <K>는 R,12.3로 치환된다.

    이러한 파라미터 표현식은 입력 파일내에서 *Include 문을 사용할 때도 쓸 수 있다. 예를 들어

    example.inp 

    ...
*Include, File=Mat, P="<E>=20E9, <DEN>=2300"
...

    mat.inp 

    *Material. Type=IsoElasticity, Name=concrete
 <E>, 0.18, ,<DEN>

    1.3.2. 고급사용법

    최상위 입력파일(*Include 문으로 포함되는 입력파일이 아닌 입력파일)에서는 *Parameter 문을 적용하여 보다 세밀하게 파라미터 문을 쓸 수 있다.

    example.inp 

    ...

*Parameter, Name=Concrete, "<E>=25E9, <nu>=0.16, <den>=2450", Default
*Parameter, Name=Steel, "<E>=200E9, <nu>=0.3, <den>=7850"

*Material. Type=IsoElasticity, Name=Wall
 <E>, <nu>, 0., <den>
...

    *Parameter는 미리 정의된 파라미터 표현식으로 이해할 수 있다. 따라서 *Parameter 표현식의 이름은 중복하여 지정할 수 없다. Default는 hfAnalyzer 실행시 -p 옵션을 사용하지 않을 때 사용하는 표현식을 의미한다. 따라서 여러개의 *Parameter 문이 있는 경우 Default 한번만 사용할 수 있다. 다음은 hfAnalyzer에서 사용한 예이다.

    > hfAnalyzer example.inp
  -> Default 속성이 있는 파라미터 표현식이 적용(여기서는 Concrete)
  -> 출력 파일 기본 이름(file base name)은 ex (example-Concrete.hdb, ...)

> hfAnalyzer example.inp -p "Concrete"
  -> Concrete로 명명된 파라미터 표현식이 적용
  -> 출력 파일 기본 이름(file base name)은 example-Concrete (example-Concrete.hdb, ...)

> hfAnalyzer example.inp -p "Steel"
  -> Steel로 명명된 파라미터 표현식이 적용
  -> 출력 파일 기본 이름(file base name)은 example-Steel (example-Steel.hdb, ...)

> hfAnalyzer example.inp -p "<E>=20E9, <nu>=0.16, <den>=2300"
  -> *Parameter 문을 사용하지 않음.
  -> 출력 파일 기본 이름(file base name)은 example-20E9-0.16-2300 (example-20E9-0.16-2300.hdb, ...)

> hfAnalzyer example.inp -p "Concrete:<E>=30E9"
  -> Concrete로 명명된 파라미터 표현식이 적용하되, <E>는 30E9를 사용
  -> 출력 파일 기본 이름(file base name)은 example-Concrete (example-Concrete.hdb, ...)

    한편 라는 특수문자열을 입력파일에 사용가능하다.

    example.inp 

    ...

*Parameter, Name=Concrete, "<E>=25E9, <nu>=0.16, <den>=2450", Default
*Parameter, Name=Steel, "<E>=200E9, <nu>=0.3, <den>=7850"

*Material. Type=IsoElasticity, Name=Wall
 <E>, <nu>, 0., <den>
...

*Step, TYPE=Static, Name=SelfWeight
...
*Print, File=<DB>-<PARAMETER>-<STEP>.prn
...

    는 입력파일, 는 파라미터문의 이름, 은 현재 해석스텝 명이다. 따라서 위 해석에서 디폴트 파라미터문이 작동하도록 실행했다면, example-Concrete-SelfWeight.prn 이 *Print 문의 대상 파일이 된다. 주의할 점은 hfAnalyzer 실행에서 -p 문을 적용하지 않고 Default 파라미터문이 사용되는 경우에도 가 치환된다는 점이다.

    > hfAnalyzer example.inp
  → Default 속성이 있는 파라미터 표현식이 적용(여기서는 Concrete)
  → 출력 파일 기본 이름(file base name)은 input (example-Concrete.hdb, ...)이나
  → Print 파일명은 example-Concrete-SelfWeight.prn

> hfAnalyzer example.inp -p "Concrete"
  → Concrete로 명명된 파라미터 표현식이 적용
  → 출력 파일 기본 이름(file base name)은 input-Concrete (example-Concrete.hdb, ...)

    1.4 단위계

    Hyfeast에서 단위계는 사용은 옵션으로 필하요하면 *Enviroment, Type=UnitSystem 명령을 통해 지정할 수 있다. 단위계가 지정을 통해 hfStudio 등에서 단위계 변환을 일괄적으로 변환할 수 있으면 어떤 객체 자체 단위계가 존재하는 경우 쉽게 통합가능하다. 다음은 관련된 일반 규칙이다.

    • Hyfeast의 기본 단위계는 *Environment, Type=UnitSystem으로 정의하는 global UnitSystem이다.
    • 일부 명령 또는 section 입력은 자기 단위를 별도로 가지는 local UnitSystem 또는 localUnitSystem을 지원한다. 대표적인 예는 다음과 같다.
    • *Function의 UnitSystem=...
    • *Section, Type=Beam에서 ShearX|ShearY|Torsion, material, localUnitSystem
    • *Section, Type=MCK의 localUnitSystem
    • *Section, Type=MovingSpring의 localUnitSystem
    • *Section, Type=Interface의 localUnitSystem
    • local UnitSystem을 지정하고 현재 global UnitSystem이 있으면, 해당 입력은 local-to-global 관계로 해석한다. 내부 변환의 의미는 각 명령이 다루는 물리량에 따라 달라진다.
    • local UnitSystem을 지정했지만 현재 global UnitSystem이 없으면, 이 값은 local metadata로 보존되며 입력 시점 에러가 되지 않는다.
    • local UnitSystem을 지정하지 않으면 현재 global UnitSystem이 정의되어 있는 경우 그 단위계를 따른다.
    • *Step의 시간값 분류는 *Step 문서를 따른다. Static, Standard/Arclength는 pseudo-time을 사용하므로 global UnitSystem과 무관하고, Dynamic은 global UnitSystem이 정의되어 있으면 그 time field를 따르는 물리 시간을 사용한다. Static, Quasi와 Seepage, Transient는 step-defined time으로 표현되는 물리 시간을 사용하며, 이 시간 단위는 step dataline의 TUnit=tUnit으로 지정한다. ConcreteTime 표준식은 day 기준이고, seepage 투수계수는 material dataline의 TUnit=tUnit으로 별도 시간 단위를 지정할 수 있다.
    • *Load, Type=LineMoving/SurfaceMoving에서 KL-510, DB-24, DB-18, DB-13.5와 같은 Design Code form을 사용할 경우 *Environment, Type=UnitSystem을 통해 정의하는 global UnitSystem이 반드시 필요하다.
    • *Section, Type=Beam에서 section DB 참조(DB, item)를 사용할 경우 DB 단위를 모델 단위로 변환해야 하므로 global UnitSystem이 반드시 필요하다. 숫자 geometry data line은 global UnitSystem이 없어도 raw 숫자로 읽을 수 있다.
    • *Include로 불러온 내용과 hfStudio의 File > Import File, File > From Clipboard, Inp Text > Apply도 같은 원칙으로 local/global UnitSystem을 해석한다.
    • force-length, force-length-time, force-length-time-temperature와 같은 세부 형식과 실제 스케일링 규칙은 각 명령 문서를 따른다.

    1.5 DB 입력

    DB 입력은 표준 단면 치수, 재료값, concrete function parameter, 시간이력 record를 직접 숫자로 모두 쓰지 않고 이름으로 불러오는 입력 방식이다. 별도 해석 객체나 새 command를 만드는 기능은 아니며, 기존 *Cell, *Material, *Function 명령의 dataline에 DB 이름이나 DB item을 쓴다. 여기서 DB는 입력 보조 데이터베이스를 뜻하며, .hdb 파일이나 *HDB 명령과는 다르다.

    Hyfeast의 DB 입력은 크게 Section DB, Material DB, TimeSignal DB source line으로 구분된다. Section DB는 *Cell에서 표준 단면 치수를 불러오고, Material DB는 *Material의 재료 물성이나 recipe뿐 아니라 concrete *Function 입력에 필요한 값을 공급한다. TimeSignal DB source line은 *Function, Type=TimeSignal에서 지진파 또는 시간이력 record를 불러온다. 대표 입력 위치는 다음과 같다.

    DB 종류 하고 싶은 일 쓰는 곳 dataline 형식 예시
    Section DB 표준 강재 단면 치수 불러오기 *Cell DB, item KSD3502-2022, H-198x99x4.5x7
    Material DB 재료 DB item으로 재료 입력하기 *Material material-db-item KDS-2026-SD400
    Material DB concrete envelope function 만들기 *Function function별 DB item dataline KDS-2026-C30
    Material DB concrete time-dependent function 만들기 *Function function별 DB item dataline ACI209-1992-C4000
    TimeSignal DB 지진파·시간이력 record 불러오기 *Function, Type=TimeSignal DB, record[, scale] DB, elcentro_1940, 1.0

    Section DB와 Material DB는 DB 값을 현재 모델 단위계에 맞게 사용하므로, 먼저 *Environment, Type=UnitSystem으로 global UnitSystem을 정의한다. TimeSignal DB source line은 record가 가진 단위 정보와 시간 간격 정보를 따르며, 세부 내용은 *Function 문서를 따른다. DB를 사용해도 *Cell, *Material, *Function의 Type= 의미는 바뀌지 않는다. Section DB에서 DB, item의 DB는 literal keyword가 아니라 KSD3502-2022, AISC16 같은 실제 DB 이름이다. TimeSignal에서 DB, record의 DB는 DB source line을 뜻하는 literal keyword다.
