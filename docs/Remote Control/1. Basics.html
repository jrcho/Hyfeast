    1. Basics

    hfStudio와 hf2DStudio의 GUI 작업을 CLI에서 자동화하는 인터페이스. 이미 띄워둔 viewer 인스턴스를 제어하거나, 반복 작업을 script로 묶거나, batch에서 대화상자 없이 처리할 때 쓴다. GUI 흐름이 익숙하지 않다면 hfStudio Help나 hf2DStudio Help를 먼저 본다.

    1.1 명령 형식

    hfStudio --remote [--target <id>] [--timeout-ms <ms>] <command> [args]
hf2DStudio --remote [--target <id>] [--timeout-ms <ms>] <command> [args]

    <id>는 list로 확인되는 전체 uuid를 권장한다.

    1.2 빠른 시작

    1. 프로그램을 일반 방식으로 실행한다.
    2. list 또는 status로 인스턴스를 확인한다.
    3. 같은 인스턴스에 계속 붙으려면 target set <id>를 쓴다.
    4. 필요한 명령을 실행한다.
    5. 반복 가능한 이력을 남기려면 script-save나 export를 쓴다.

    1.3 공통 규칙

    • Target 선택: --target이 없으면 저장된 기본 target 사용. 없고 인스턴스가 정확히 하나면 자동 선택, 모호하면 실패한다.
    • 경로와 따옴표: 절대 경로는 그대로, 상대 경로는 CLI 작업 디렉터리 기준. 공백 포함 인자는 큰따옴표가 필요하다.
    • 비대화형: GUI modal 입력이 필요한 동작은 prompt 없이 실패한다.
    • Script와 런타임 파일: script는 한 줄에 command tail 하나. --remote나 --target은 script 안에 넣지 않는다. history, target, replay, backup 같은 런타임 파일은 현재 workspace root의 .hyfeast/에 저장되며 backup-*만 자동 정리된다.
    • 종료 코드: 성공 0, 사용법 오류 2, target 실패 3, 연결 실패 4, timeout 5.

    1.4 Workspace root와 런타임 파일

    hfStudio와 hf2DStudio는 IPC history, target metadata, replay input, backup 파일을 workspace root 아래의 .hyfeast/에 저장한다. workspace root는 다음 순서로 정한다.

    1. 시작 인자로 모델 파일을 받으면 그 파일의 폴더를 사용한다.
    2. GUI나 Remote Control로 .hdb 또는 .hf2d 파일을 열면 해당 파일의 폴더로 전환한다.
    3. 빈 hfStudio 모델에서 .inp를 import하면 저장 전까지 그 .inp 파일의 폴더를 사용한다.
    4. Save As로 .hdb 또는 .hf2d 파일을 만들면 저장 파일의 폴더로 전환한다.
    5. export, write-scene, script 실행 파일 경로는 workspace root를 바꾸지 않는다.
    6. 아직 파일이 없는 Untitled 세션은 현재 workspace root를 유지한다. 파일 없이 처음 시작한 경우에는 시작 작업 폴더가 workspace root다.

    Remote Batch에서 새 hfStudio 또는 hf2DStudio 인스턴스를 실행하면 현재 workspace root를 시작 작업 폴더로 넘긴다.
