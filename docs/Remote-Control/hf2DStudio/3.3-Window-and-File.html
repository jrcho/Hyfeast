    3.3 hf2DStudio 원격 제어 창과 파일

    3.3.1 Remote-only

    • 먼저 실행 중인 인스턴스를 확인하고, remote control이 정상 동작하는지 점검할 때 사용한다.
    hf2DStudio --remote list
hf2DStudio --remote target <set|show|clear> [id]
hf2DStudio --remote [--target <id>] status
hf2DStudio --remote [--target <id>] ping
hf2DStudio --remote [--target <id>] focus
hf2DStudio --remote [--target <id>] maximize
hf2DStudio --remote [--target <id>] minimize
hf2DStudio --remote [--target <id>] [--timeout-ms <ms>] script <file>
hf2DStudio --remote [--target <id>] script-save [file]
    • target: --target 생략 시 사용할 로컬 기본 대상을 관리한다. 자세한 내용은 아래 target 절과 Remote Control Basics를 참고한다.

    3.3.1.1 list

    • 현재 실행 중인 모든 hf2DStudio 인스턴스를 나열한다.
    • 문법: list
    • 검증: 위치 인수를 받지 않는다.
    • 동작: 각 줄은 uuid | pid | server | startedAt | file 형식이며, target 명령이나 --target <id>에 그대로 넣을 수 있는 uuid를 맨 앞에 보여준다. 실행 중인 인스턴스가 없으면 안내 문구를 출력하고 성공 종료 코드(0)로 끝난다. 이 명령은 로컬 클라이언트에서만 동작하며 대상 인스턴스로 IPC 요청을 보내지 않는다.

    예시:

    hf2DStudio --remote list

    3.3.1.2 target

    • --target이 생략됐을 때 사용할 기본 대상 인스턴스를 로컬에 저장한다.
    • 문법: target set <id> target show target clear
    • 검증: set은 정확히 하나의 <id> 인자가 필요하며, 이 id는 list에서 보이는 uuid 또는 server name이어야 한다. show와 clear는 추가 인수를 받지 않는다. --target 옵션은 target 명령에 함께 쓸 수 없다.
    • 동작: set은 id를 resolve한 뒤 runtime 디렉터리에 저장하고, 결과 JSON을 출력한다. show는 저장된 기본 대상을 JSON으로 반환하며, 해당 인스턴스가 여전히 살아 있는지 함께 표시한다. clear는 저장된 기본 대상을 제거한다. 이 명령은 로컬 클라이언트에서만 동작한다.

    예시:

    hf2DStudio --remote target set 4e37d050-cda4-4a24-a885-4e0595554802
hf2DStudio --remote target show
hf2DStudio --remote target clear

    3.3.1.3 status

    • 대상 인스턴스의 현재 상태를 JSON으로 반환한다.
    • 문법: status
    • 검증: 위치 인수를 받지 않는다. 대상 인스턴스가 있어야 한다.
    • 동작: uuid, server name, 현재 파일 경로, 실행 시작 시각, 저장되지 않은 변경 유무 등을 포함한 JSON을 출력한다. section model 데이터는 바꾸지 않고 Remote Control History에도 아무 줄도 남기지 않는다.

    예시:

    hf2DStudio --remote status

    3.3.1.4 ping

    • 대상 인스턴스와의 IPC 연결 상태를 확인한다.
    • 문법: ping
    • 검증: 위치 인수를 받지 않는다.
    • 동작: 연결과 응답이 정상이면 성공 종료 코드로 끝난다. section model 데이터를 바꾸지 않고 Remote Control History에도 아무 줄도 남기지 않는다. 자동화 스크립트에서 대상 창이 응답 가능한지 빠르게 확인할 때 사용한다.

    예시:

    hf2DStudio --remote ping

    3.3.1.5 Window State

    hf2DStudio --remote [--target <id>] focus
hf2DStudio --remote [--target <id>] maximize
hf2DStudio --remote [--target <id>] minimize
    • focus는 필요하면 창을 일반 상태로 복원한 뒤 앞으로 가져오고 활성화한다.
    • maximize는 대상 창을 최대화한 뒤 앞으로 가져오고 활성화한다.
    • minimize는 대상 창을 최소화한다.
    • 이 명령들은 remote-only UI 보조 명령이며, section model 데이터는 바꾸지 않고 Remote Control History에도 canonical command tail을 남기지 않는다.

    예시:

    hf2DStudio --remote maximize
hf2DStudio --remote focus
hf2DStudio --remote minimize

    3.3.1.6 script

    • 대상 인스턴스에서 스크립트 파일을 한 줄씩 순차 실행한다.
    • 문법: script <file>
    • 검증: <file>은 존재해야 한다. 상대 경로는 CLI 현재 작업 디렉터리를 기준으로 해석한다. 파일의 각 줄은 hf2DStudio --remote 접두사 없이 command tail만 담아야 한다. #으로 시작하는 줄과 빈 줄은 주석으로 무시한다.
    • 동작: 중간의 한 줄이라도 실패하면 SCRIPT_FAILED로 중단하고, 실패한 줄 번호와 원본 오류 코드/메시지를 보고한다. 실행 중 quit를 만나면 그 줄까지의 실행 횟수를 성공 결과로 반환하고 대상 창이 닫힌다. --timeout-ms는 개별 줄이 아니라 script 요청 전체에 적용되므로, 긴 스크립트에는 넉넉한 값을 지정한다.

    예시:

    hf2DStudio --remote --timeout-ms 60000 script D:\Work\build-section.txt

    3.3.1.7 script-save

    • 대상 인스턴스가 누적한 Remote Control History를 스크립트 파일로 저장한다.
    • 문법: script-save [file]
    • 검증: [file]을 생략하면 <sessionRoot>/.hyfeast/ 아래의 기본 스크립트 출력 경로에 저장한다. [file]을 지정하면 그 경로로 저장하며, 상대 경로는 CLI 현재 작업 디렉터리를 기준으로 해석한다.
    • 동작: 기본 주석 헤더(# One command tail per line (without "hf2DStudio --remote"))와 누적된 명령 tail을 UTF-8·CRLF로 기록한다. GUI Command 패널에서 보이는 명령 이력과 동일한 줄 집합이 저장된다. 저장한 파일은 그대로 script 명령의 입력으로 재생할 수 있다.

    예시:

    hf2DStudio --remote script-save D:\Work\section-recipe.txt

    3.3.2 File

    • 스크립트나 배치 흐름에서 section model을 생성, 열기, import, 저장, 종료할 때 사용한다.
    hf2DStudio --remote [--target <id>] new [--discard-unsaved]
hf2DStudio --remote [--target <id>] open <file>
hf2DStudio --remote [--target <id>] import-dxf-geometry <file>
hf2DStudio --remote [--target <id>] save [file]
hf2DStudio --remote [--target <id>] quit [--discard-unsaved]
    • new:
    • --discard-unsaved가 없으면 GUI File > New와 같은 저장 확인 흐름을 따른다.
    • Yes: 현재 section을 먼저 저장한다. 아직 한 번도 저장한 적이 없으면 Save As 대화상자가 열린다.
    • No: 미저장 변경을 버리고 새 빈 section model을 만든다.
    • Cancel: 현재 section을 유지한 채 명령이 NEW_FAILED로 끝난다.
    • open, quit:
    • 미저장 변경이 있고 현재 파일 경로가 있으면 먼저 자동 저장한다.
    • 미저장 변경이 있는데 현재 파일 경로가 없으면 SAVE_PATH_REQUIRED로 실패한다. 단, Untitled 모델의 사용자 변경이 시작 UnitSystem 선택뿐이면 저장 없이 계속 진행한다.
    • import-dxf-geometry <file>:
    • DXF 파일의 지원 엔터티를 현재 active section의 Geometry 선분으로 가져온다.
    • hfStudio DXF importer와 같은 LINE, LWPOLYLINE, POLYLINE, ARC, CIRCLE, ELLIPSE, SPLINE 읽기 경로를 사용하고, 결과 Geometry Guide primitive를 Line, Arc, Bezier, Spline curve로 변환한다.
    • DXF의 최종 WCS z 좌표는 무시하고 (x, y)만 hf2DStudio Geometry 좌표로 사용한다.
    • DXF $INSUNITS와 active section/global unit이 모두 유효할 때만 단위 스케일을 변환한다. 둘 중 하나가 없거나 지원되지 않는 DXF unit이면 스케일 변환 없이 좌표값을 그대로 사용한다.
    • active section에 mesh가 이미 있으면 원격 명령은 실패한다. 먼저 make-mesh delete로 mesh를 삭제한 뒤 실행한다.
    • new --discard-unsaved:
    • 미저장 변경을 즉시 버린다.
    • GUI 저장 확인 대화상자를 띄우지 않는다.
    • 호출자가 의도적으로 비대화형 폐기를 원할 때만 사용한다.
    • quit --discard-unsaved:
    • 자동 저장 없이 미저장 변경을 버리고 종료한다.
    • GUI 저장 확인 대화상자를 띄우지 않는다.
    • 원격 요청이 수락되면 대상 창을 바로 닫는다.
    • save [file]:
    • [file]이 없으면 현재 파일에 저장한다.
    • [file]이 있으면 해당 경로로 저장하고 현재 파일 경로도 함께 갱신한다.
