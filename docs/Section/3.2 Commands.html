    3.2 Command's Manual

    3.2.1 일반 사항

    hfSectAnalyzer/hf2DStudio에 사용되는 입력화일은 hfAnalyzer/hfStudio와 동일하게 Keyword를 갖는 블록을 갖는 텍스트 파일이다. #는 주석을 나타내는 문자이고, 이 문자 뒤의 문자열은 무시된다. 공백라인 역시 무시된다. Name 키워드에 따라오는 name을 제외하고는 대소문자를 구분하지 않는다. canonical section-model 확장자는 .hf2d이다. 사용되는 키워드는 *Environment, *Function, *Material, *Section, *SectionStop, *SectionSignal, *SectionAnalysis 등 이다. 이중 *Function, *Material, *Section은 hfAnalyzer와 공유하는 명령어이며, 나머지는 hfSectAnalyzer/hf2DStudio에서만 사용되는 명령어이다.

    *Environment, Type=UnitSystem
 force-length-time-temperature

*Function, TYPE=type, Name=name
...

*Material, TYPE=UGeneric, Name=name
...

*Geometry, Name=name
 ...

*Section, TYPE=Beam, Name=name
 *CellMeshPoint
  ...
 *Cell, TYPE=Recta


*SectionStop
  material, min_strain, max_strain  
  ...

*SectionSignal
  material, strain, msg
  ...

*SectionAnalysis, Name=name, Section=section,Left|Right Ref=angle,yp,zp, Output=Preselect|All
 *SectionStep, ExtLoad=a,b,EK|EM|NK|NM, Inc=inc
  InitialStress|Stress, cellId, value
  ...
 *SectionStep, ...
  ...
 *SectionStepPM, MaxDeform=maxAxial,maxKappa, Inc=1000, PMPoints=50

*SectionAnalysis, Name=name, Section=section
...

    작성된 입력파일은 확장자는 강제조항은 아니지만 canonical workflow에서는 .hf2d를 사용한다. 해석을 수행하면 log 파일과 xlsx 파일이 생성된다. log 파일은 계산된 단면상수와 함께 계산진행 과정을 표출한다. xlsx 파일은 비선형단면해석을 수행하는 경우(즉, *SectionAnalysis가 존재하는 경우) 그 해석 결과값을 저장한다. 예를 들어 RCColumn.hf2d에 대해 해석을 수행하면 RCColumn.xlsx 파일에 비선형 단면 해석결과가 저장되고, RCColumn.log 파일에서 확인할 수 있다.

    3.2.2 *Environement, TYPE=UnitSystem

    단위계를 지정한다. 만약 이 명령이 없는 경우 단위계를 사용하지 않는다는 의미이다. 가능한 단위계는 다음과 같다.

    • force: N, kN, kgf, tonf, lbf, kip
    • length: m, cm, mm, km, in, ft, yd, mi
    • time: s, min, hr, day
    • temperature: K, C, F

    hfSectAnalyzer와 hf2DStudio의 global *Environment, TYPE=UnitSystem 문법도 hfAnalyzer와 hfStudio와 동일한 4필드 형식을 사용한다.

    3.2.3 *Function

    재료 모델 정의시 필요한 함수를 정의한다. hfAnalyzer에서 정의한 다양한 함수 중에서 아래의 타입만 사용가능하다.

    *Function, TYPE=Multilinear/ParabolaCEnv/HognestadCEnv/EC2CEnv/MPPCEnv/MaekawaTEnv/ConcreteTime

    입력 상세는 공유 *Function 명령 매뉴얼을 따른다. 콘크리트 envelope function은 dataline에서 콘크리트 물성 DB item을 사용할 수 있지만 허용 기준은 function type별로 다르다. ParabolaCEnv는 단면해석용 입력으로 KDS-2026-C<fck>, EC2-2004-C<fck>만 받으며 ToDirectForm 앞에 alpha를 둘 수 있다. HognestadCEnv는 KDS-2026-C<fck>, ACI318-2025-C<fck>, EC2-2004-C<fck>를 받는다. EC2CEnv는 KDS-2026-C<fck>와 EC2-2004-C<fck>를 받는다. MPPCEnv와 MaekawaTEnv는 KDS-2026-C<fck>, ACI318-2025-C<fck>, EC2-2004-C<fck>를 받는다. DB function 입력은 현재 global unit system으로 해석하며 local UnitSystem=... keyword를 허용하지 않는다. HognestadCEnv, EC2CEnv, MPPCEnv는 ToDirectForm 앞에 EciCurve를 둘 수 있다. ConcreteTime은 사용자 정의 function 참조형과 EC2/KDS/ACI 기준식 dataline을 모두 지원한다. 사용자 정의형은 global UnitSystem을 요구하지 않지만, 기준식 dataline은 현재 global UnitSystem을 요구하며 local UnitSystem=... keyword를 허용하지 않는다.

    3.2.4 *Material

    일축 재료 모델을 정의한다. hfAnalyzer에서 정의한 다양한 재료모델 중 아래의 타입만 사용가능 하며, 포아송비, 밀도, 온도팽창계수 등의 물성치는 무시된다. 

    *Material, TYPE=IsoElasticity/vonMises/UGeneric/USteel

    입력 상세는 공유 *Material 명령 매뉴얼을 따른다. UGeneric material dataline에는 콘크리트 DB item을 직접 쓰지 않는다. 먼저 압축·인장 envelope function을 정의하고, UGeneric에서는 해당 function 이름을 참조한다. 압축 envelope와 인장 envelope의 초기기울기는 서로 다를 수 있으며, UGeneric은 각 function을 입력된 대로 사용한다.

    3.2.5 *Geometry

    *Geometry는 *Geometry, Name=<name> 형식으로 쓰는 top-level 형상 블록이다. canonical .hf2d workflow에서는 같은 이름의 *Section, TYPE=Beam, Name=<same-name>와 name으로 연결된다. hf2DStudio에서 단면 스케치를 그리고, face/rebar를 편집하고, 메쉬를 생성할 때 사용하는 2차원 형상 원본을 정의한다. 같은 .hf2d 파일을 hfSectAnalyzer도 읽지만 해석 시에는 이 블록을 무시하므로, 실제 해석에는 생성된 *CellMeshPoint와 *Cell 데이터가 사용된다.

    *Geometry 명령행에는 geometry 이름과 선택적인 taper 정보만 있고, 직접 데이터라인은 없다. 실제 형상은 *Point, *Curve, *Face, *FaceHint, *Rebar 같은 하위 블록으로 기술한다. taper 단면에서는 같은 point의 좌/우 좌표가 linked geometry로 유지된다. hf2DStudio에서 메쉬를 만든 뒤에는 짝이 되는 *Section, TYPE=Beam 블록에 생성된 direct section mesh가 기록된다. 이때 현재 메쉬 차수와 mesher 경로에 따라 *Cell, TYPE=Mesh connectivity는 T3, Q4, T6, Q8 중 하나가 된다.

    *Geometry, Name=RectRC
 *Point
  ...
 *Curve
  ...
 *Face, 1, conc
  ...
 *FaceHint, 1, 11, 12, 13, 14
 *Face, 2, conc
  ...
 *FaceHint, 2, 21, 22, 23, 24
 ...
 *Rebar, 1, rebar, 25
  ...
 *Rebar, 2, rebar, 25
  ...

*Section, TYPE=Beam, Name=RectRC
 *CellMeshPoint
  ...
 *Cell, TYPE=Mesh
  ...

    실무적으로는 *Point와 *Curve를 각각 한 번 두고, 그 아래에 필요한 개수만큼 *Face, *FaceHint, *Rebar를 배치한다고 이해하면 된다. 즉 *Point로 기준 점을 정의하고, *Curve로 경계를 만들고, *Face로 닫힌 영역과 재료를 정의하고, 필요하면 *FaceHint로 해당 face의 quad mesh corner hint를 추가하고, *Rebar로 형상 점 기반 철근 그룹을 정의한다. hf2DStudio에서 메쉬를 만들면 최종 해석용 단면은 *CellMeshPoint와 *Cell로 기록된다.

    하위 블록의 형식과 의미는 다음과 같다.

    3.2.5.1 *Point

    *Point
 id, y, z {, y, z}  
 ...

    데이터라인 한 줄이 점 하나를 정의한다. 점 ID는 *Geometry 블록 안에서 중복되면 안 된다. taper 단면에서는 같은 점의 좌측 단면 좌표와 우측 단면 좌표를 한 줄에 같이 쓰며 linked geometry로 유지된다. 뒤쪽 y,z는 taper 단면일 때 정의한다.

    3.2.5.2 *Curve

    *Curve
 id, Line, seed, startPoint, endPoint
 id, Arc, seed, startPoint, middlePoint, endPoint
 id, Bezier, seed, point0, point1, point2[, w1]
 id, Bezier, seed, point0, point1, point2, point3[, w1, w2]
 id, Spline, seed, point1, point2, ..., pointN
    seed는 해당 곡선을 따라 메쉬를 나눌 분할 개수이다. Line은 점 ID 2개, Arc는 점 ID 3개(start, mid, end), 2차 Bezier는 점 ID 3개, 3차 Bezier는 점 ID 4개를 사용한다. Arc는 세 점이 서로 달라야 하고 일직선 위에 있으면 안 된다. rational bezier는 같은 Bezier 키워드를 쓰되 2차에서는 내부 가중치 w1 하나, 3차에서는 내부 가중치 w1, w2를 추가로 줄 수 있다. 3점 Section Bezier에서 w1을 생략하면 기존 section 곡선 해석과 같은 방식(w1 = 1/sqrt(2))으로 처리된다. 순수 2차 bezier가 필요하면 w1 = 1.0을 명시하면 된다. 가중치 하나만 줄 때는 1.0, 0.70710678처럼 실수 표기를 사용해야 하며, 정수 토큰 하나만 쓰면 3차 bezier의 네 번째 점 ID로 해석된다. 4점 Bezier에서 가중치를 생략하면 내부 가중치는 모두 1.0으로 본다. Spline은 점 ID 2개 이상을 사용한다. 참조하는 점은 모두 먼저 *Point에서 정의되어 있어야 한다.

    3.2.5.3 *Face

    *Face, faceId, material
 +curve1, +curve2, -curve3, ...
 [필요하면 추가 loop 라인]
    명령행에서 face ID와 재료 이름을 지정한다. 뒤따르는 각 데이터라인은 부호가 붙은 curve ID들로 하나의 닫힌 loop를 정의한다. +는 저장된 curve 방향을 그대로 쓰고, -는 반대 방향으로 사용한다. 추가 loop 라인을 두면 내부 구멍도 표현할 수 있다.

    • *FaceHint 
      *FaceHint, faceId, p1, p2, p3, p4
      이미 정의된 face에 대한 quad mesh corner hint 4개를 지정한다. 문법은 faceId로 연결되는 독립 명령이며, 가독성을 위해 대응하는 *Face 바로 뒤에 두는 것을 권장한다. p1..p4는 서로 다른 4개의 point ID여야 하고, 모두 해당 face의 outer loop join point여야 한다. TFI meshing이 활성화되어 있으면 mesher는 automatic corner detection보다 먼저 이 hint를 사용해 TFI patch의 네 모서리를 잡는다. Linear mesh 생성에서는 Q4 요소가 만들어지고, quadratic mesh 생성에서는 Q8 요소가 만들어진다.

    3.2.5.4 *Rebar

    *Rebar, rebarId, material, diameter[, diameterRight]
 pointId1, pointId2, ...
 [필요하면 추가 point 라인]
    명령행에서 철근 그룹 ID, 재료 이름, 직경을 지정한다. 뒤따르는 데이터라인에는 철근을 배치할 형상 점 ID들을 적는다. taper 단면에서는 우측 단면 직경 diameterRight를 추가로 줄 수 있다.

    • 개수 규칙 하나의 *Geometry 블록 안에서는 *Point와 *Curve는 각각 한 번만 둘 수 있고, *Face, *FaceHint, *Rebar는 여러 번 사용할 수 있다.

    3.2.6 *Section, TYPE=Beam

    hfAnalyzer에서 정의한 다양한 단면 중 Beam 타입을 사용할 수 있다. 하위 명령으로 사용되는 명령어는 *CellMeshPoints, *Cell 등이 있다.

    메쉬 기반 단면의 경우 hf2DStudio는 생성된 direct mesh connectivity를 그대로 기록한다. 즉 *Cell, TYPE=Mesh 블록은 더 이상 선형 T3/Q4 셀로만 제한되지 않는다. 같은 section 블록 안에서 하나의 *CellMeshPoint 테이블을 공유하며 T3, Q4, T6, Q8 셀을 기술할 수 있다.

    3.2.6.1 *CellMeshPoint

    *CellMeshPoint
 pointId, y, z {, y, z}
 ...

    뒤쪽 y,z는 taper 단면일 때 정의한다.

    3.2.6.2 *Cell

    이들 명령은 hfAnalyzer와 동일하나 사용가능한 *Cell은 다음과 같다. 

    *Cell, TYPE=Point/*Cell, TYPE=Point,Circle
*Cell, TYPE=Layer/*Cell, TYPE=Layer,Circle,/*Cell, TYPE=Layer,Stack
*Cell, TYPE=H/T/C/L/2C/2L/HR[-YUp]
*Cell, TYPE=Mesh/*Cell, TYPE=Mesh,Circle/*Cell, TYPE=Mesh,Rectangle
*Cell, TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp]

    TYPE=H/T/C/L/2C/2L/HR[-YUp]은 표준 강재 형상을 직접 형상 cell로 정의하며 ShapeSection으로 처리하고, 탄성 재료(IsoElasticity)만 사용할 수 있다. TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp]은 같은 표준 형상 데이터에서 실제 material point mesh를 생성하며 MeshedSection으로 처리하고, 일반 Mesh 셀처럼 탄성/비탄성 재료를 사용할 수 있다. 표준 형상 치수는 hf2DStudio template mesh 기준을 따른다. HR은 H, B, t, r을 사용하고, r=0이면 내외부 코너를 모두 sharp corner로 생성하며, r>0이면 outer corner radius를 r+t로 생성한다. 다른 표준 형상 data line은 해당 형상에서 의미 있는 B2, tf2, c, r1~r4 항목만 포함한다. 형상 높이를 local y 방향으로 둘 때는 H-YUp 또는 Mesh,H-YUp처럼 형상 token에 -YUp을 붙인다. TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp] 생성형에서는 첫 번째 data line 끝에 ToDirectForm을 붙여 생성된 mesh를 일반 *CellMeshPoint 및 *Cell, TYPE=Mesh 데이터로 저장할 수 있다.

    TYPE=Mesh를 쓰는 경우 각 mesh-cell 데이터라인은 생성된 단면 메쉬에 따라 3, 4, 6, 8개의 point ID를 참조할 수 있다. 표준 형상 template mesh는 Q8 사각 cell과 T6 quarter-fillet cell을 포함할 수 있으며, r>0인 HR 코너는 annular-corner Q8 cell을 포함할 수 있다. T3/T6 셀은 triangle ordering을 사용하며, 먼저 corner node를 쓰고 뒤에 midside node를 쓴다. Q4/Q8 셀은 quadrilateral ordering을 사용하며, 먼저 corner node를 쓰고 뒤에 edge midside node를 쓴다. hf2DStudio는 section 블록을 export할 때 이 connectivity를 그대로 유지한다.

    section DB 참조는 숫자 형상 data line 대신 DB, item 형식으로 쓴다. taper section에서는 두 번째 data line도 다른 DB 참조로 지정할 수 있다. AISC16 item은 W/M/S/HP, WT/MT/ST, C/MC, L, 2L, HSS, Pipe 같은 AISC designation 시작 형식을 사용하고, KSD3502-2022 item은 H-, T-, C-, 2C-, L-, 2L-처럼 Hyfeast cell type prefix를 포함한다. 예를 들어 H 항목은 H-HxBxtwxtf 형식이다. AISC16의 round HSS와 PIPE는 Circle, rectangular/square HSS는 HR 또는 Mesh,HR을 사용한다. 표준 형상 DB 참조는 저장/재출력 시 유지되지만, 생성형 mesh cell에서 ToDirectForm을 쓰면 direct mesh form으로 저장된다. Circle 및 Mesh,Circle DB 참조는 숫자 circle data로 저장된다.

    3.2.7 *SectionStop

    필요에 따라 재료를 대상으로 단면해석을 종료할 변형률을 지정한다.

    3.2.8 *SectionSignal

    재료를 대상으로 단면해석시시 출력할 메시지를 지정한다.

    3.2.9 *SectionAnalysis

    단면 해석을 지정한다. 하위 명령으로 *SectionStep, *SectionStepPM이 있다. *SectionStep은 단면해석 단계를 지정하고, *SectionStepPM은 PM 다이어그램을 계산하는 해석 단계를 지정한다. *SectionStop은 재료(material), 해석을 멈출 최소(min_strain), 최대 변형률(max_strain)을 데이터라인에 기입한다. *SectionSignal은 재료(material)과 메시지를 출력할 변형률 조건(strain), 출력 메시지(msg)를 기입한다. 이 두 명령은 옵션이다. 다음은 사용예이다. 

    *SectionStop
 conc,-0.005,
 rebar,-0.08,0.08

*SectionSignal
 conc, 0.0001042, "Concrete Tesile Failure"   
 rebar, 0.002, "Rebar Yield“

    *SectionAnalysis에서 name은 해석명을 의미하며 xlsx 파일내의 시트명을 만드는 기준이 된다. Section=section, Left|Right에서 section은 해석대상 단면 이름이다. Left와 Right에서 taper 단면으로 정의되는 경우 시작단면 또는 끝단면 중 어느것을 사용할 지는 지정한다(디폴트는 Left) Ref=angle,yp,zp는 기준점과 회전각(degree)이다(디폴트는 0,0,0). Output에서 Preselect를 지정하면 각 cell에서 상하연단에서만 응력과 변형률을 출력해며, All은 모든 재료점에서 응력과 변형률을 출력한다(디폴트는 Preselet). *SectionStep, *SectionStepPM는 *SectionAnalysis의 하위명령어로 단면 해석을 지정한다. *SectionStep은 단면변형률 또는 단면력을 지정하는 일반적인 단면해석을 의미한다. ExtLoad에서 해석유형 EK, EM, NK, NM 에 따라 도달해야 할 값 a, b를 지정하며, Inc=inc는 증분개수이며, 옵션이며 디폴트값은 1이다.

    • ExtLoad=a,b,EK : 축변형과 곡률이 각각 a, b가 될 때 까지 해석
    • ExtLoad=a,b,EM : 축변형과 모멘트가 각각 a, b가 될 때 까지 해석
    • ExtLoad=a,b,NK : 축력과 곡률이 각각 a, b가 될 때 까지 해석
    • ExtLoad=a,b,NM : 축력과 모멘트가 각각 a, b가 될 때 까지 해석

    다음 예는 축력은 0을 유지한채, 곡률이 0.00004가 될 때까지 증분 개수 100개로 해석하라는 의미이다. 

    *SectionAnalysis, Name=E1, Section=section
 *SectionStep, ExtLoad=0.,0.00004,NK, Inc=100

    *SectionStep은 연이어 지정할 수 있는데, 이를 통해 단계별 단면해석이 가능하다. 다음은 축력은 10 가력한 후, 축력을 유지한채 곡률을 변화시켜 파괴시 까지 해석하는 예이다. 

    *SectionAnalysis, Name=E1, Section=section
 *SectionStep, ExtLoad=10.,0.,NM
 *SectionStep, ExtLoad=10.,0.04,NK, Inc=100   # Assumption : 0.04 is large enough to fail the section

    *SectionStep의 데이터라인으로 필요할 경우 초기응력(InitialStress) 또는 도달해야할 응력(Stress)를 단면을 구성하는 셀(cell) 단위로 지정할 수 있다. InitialStress은 프리텐션, Stress로 포스트텐션을 지정할 수 있다. cellId는 셀의 아이디, value는 응력값이다. 예를 들어 IntialStress, 2, 1000은 2번 셀을 1000의 초기응력으로 해석을 시작하라는 의미이다. Stress, 3, 1000은 최종 단계에서 3번 셀이 1000의 응력 상태를 갖도록 해석된다. Stress, 1, 0 과 같이 지정하면 1번 셀이 없는 것과 같은 효과를 낼 수 있다. 다음은 프리텐션을 2번 셀에 가력한후, 축력 가력, 파괴시까지 곡률을 가력하는 형태의 해석이다. 

    *SectionAnalysis, Name=PHC500A-N2 Section=PHC500A
 *SectionStep, ExtLoad=0.,0.,NM, Inc=1
   InitialStress, 2, 994.625  # 0.7*fpu
 *SectionStep, ExtLoad=-1766000,0,NM, Inc=1  
 *SectionStep, ExtLoad=-1766000,0.02/250,NK, Inc=1000

    *SectionAnalysis내에서 수행되는 *SectionStep의 결과가 name 시트에 저장된다. 출력파일은 다음과 step number, 단면 축변형과 단면 축력(Ex와 Nx), 곡률과 휨모멘트(Kz, Mz), 셀의 재료점에서의 변형률과 응력(E.C1.1, S.C1.1 등), 메시지(Msg.) 등을 열로 갖는 시트 이다. 

    step, Ex, Nx, Kz, Mz, E.C1.1, S.C1.1, ..., Msg.
...

    *SectionStepPM은 PM 다이어그램을 해석하기 위한 명령어이다. 내부적으로 축력수준을 바꾸어가며 단면해석을 수행한다. 먼저 축력만 가력할때의 파괴하중을 계산하는데 이때 축변형값 maxAxial을 이용해 가력하게 된다. 따라서 maxAxial은 압축파괴가 발생할 수 있는 충분히 큰 값이어야 한다. 축력 파괴하중을 기준으로 축력 수준을 낮추어 곡률 변화에 따른 파괴해석을 수행하게 된다. pmpoints는 이때 사용하는 PM 다이어그램상의 점, 즉 축력 수준을 의미한다. maxKappa는 각 파괴해석시 최대 곡률을 정의하는 데 사용되므로, 파괴가 발생할 수 있도록 충분히 큰 값을 지정해야 한다. inc는 개별 파괴해석에서 사용하는 증분 개수이다. 다음은 철근콘크리트 단면을 대상으로 PM 해석을 수행한 예이다. 

    *SectionAnalysis, Name=RCSec, Section=RCSec
 *SectionStepPM, MaxDeform=-0.005,0.02/250, Inc=1000, PMPoints=50

    *SectionAnalysis내에서 한번만 지정할 수 있으며, *SectionStep 이후 지정할 수 있으나 최종 해석 단계여야 한다. 다음은 프리텐션 부재를 대상으로 PM 해석을 수행한 예이다. 

    *SectionAnalysis, Name=PHC500A Section=PHC500A
 *SectionStep, ExtLoad=0.,0.,NM, Inc=1
   InitialStress, 2, 994.625  # 0.7*fpu
 *SectionStepPM, MaxDeform=-0.005,0.02/250, Inc=1000, PMPoints=50

    *SectionStepPM은 pmpoint 만큼의 단면해석을 수행한 것으로 이해할 수 있다. 이때 개별 단면해석의 결과를 name-pm@plevel 시트에 저장하게 되고, 파괴시의 단면변형/단면력을 정리하여 name-pm 시트에 저장한다. 위 예에서 PMPoints=50이므로 다음과 같은 파일이 생성된다.

    PHC500A-PM@0 : 축력이 0인 경우 PHC500A-PM@2 : 축력이 파괴축력의 2%인 경우 ... PHC500A-PM@100 : 축력이 파괴축력의 100%인 경우 (모멘트는 0) PHC500A-PM : 파괴시 축력레벨에 따른 단면변형/단면력 파일

    name-PM 시트는 다음과 같은 포맷이다.
