    2 입력

    2.1 *Material, Type=User

    사용자 재료 플러그인(DLL)으로 재료를 정의한다.

    *Material, Type=User, Name=name
 library[, symbol][, NState=nstatv][, NProps=nprops][, Unsymm=Yes|No][, Thread=Yes|No][, Density=density]
 props_1, props_2, ...
 [props_n+1, ...]
    Keyword line
    • Name=name: 재료 이름. 80자 이하여야 한다. 이름은 플러그인에 CMNAME으로 전달된다.
    First dataline (required)
    • library: 플러그인 DLL 경로(required). 절대 경로를 권장한다. 상대 경로는 해석기가 읽는 입력 파일의 폴더(HDB로 실행하면 HDB 파일의 폴더)를 먼저, 그다음 작업 폴더를 기준으로 찾는다. 폴더 구분자는 \와 /를 모두 쓸 수 있다(예: plugins/mymat.dll, D:/UMAT/mymat.dll). 경로에 공백이 있으면 큰따옴표로 감싼다.
    • symbol: 호출할 함수 이름(optional, default hf_umat_v1).
    • NState=nstatv: 사용자 상태변수(STATEV) 개수(optional, default 0). Abaqus *DEPVAR에 해당한다.
    • NProps=nprops: 물성 개수(optional). 주면 PROPS 값의 총개수와 같아야 하며, 다르면 입력 오류로 멈춘다. Abaqus *USER MATERIAL, CONSTANTS=n의 n을 옮기면 된다.
    • Unsymm=Yes|No: Yes이면 플러그인이 돌려준 비대칭 접선강성을 그대로 쓴다. No이면 \((C+C^T)/2\)로 대칭화한다(optional, default No). Abaqus *USER MATERIAL, UNSYMM에 해당한다.
    • Thread=Yes|No: Yes이면 플러그인을 여러 스레드에서 동시에(병렬로) 부른다. 같은 DLL을 쓰는 재료 중 하나라도 No이면 그 DLL의 모든 재료 호출을 한 번에 하나씩 차례로 실행한다(optional, default Yes). 언제 No가 필요한지는 2.3절에 있다.
    • Density=density: 질량과 자중에 쓰는 밀도(optional, default 0). Abaqus *DENSITY에 해당한다.

    library와 symbol 뒤의 키=값 항목은 생략할 수 있고 순서는 자유다. 키는 대소문자를 구분하지 않으며, 같은 키는 한 번만 쓸 수 있다.

    PROPS datalines (required)
    • props_1, props_2, ...: 둘째 데이터라인부터는 모두 재료 물성(PROPS)이며, 여러 줄을 순서대로 이어 붙인다. 숫자만 쓸 수 있고 빈 값(1,,2)은 쓸 수 없다.

    2.2 입력 규칙

    • 단위: Hyfeast는 PROPS의 의미를 모르므로 단위를 변환하지 않는다. 모델 단위계로 입력한다. 모델과 다른 UnitSystem을 가진 파일에서 사용자 재료를 읽으면 입력 오류로 멈춘다. hfStudio에서도 사용자 재료의 단위 변환이 필요한 전역 단위계 변경을 거부하며, 기존 모델 값과 단위계를 유지한다.
    • DLL 경로: hfStudio에서 다른 폴더의 .inp를 불러와 다른 곳에 HDB로 저장하면 상대 경로의 기준이 바뀐다. DLL을 입력 파일과 함께 옮기지 않는다면 절대 경로를 쓴다.
    • DLL 로드 시점: DLL은 입력을 다 읽은 뒤 해석을 시작하기 전에 한 번 불러오며, 모델의 모든 사용자 재료 DLL이 있어야 한다. *TestMaterial은 입력을 읽는 도중 실행되므로 그 명령이 쓰는 재료의 DLL을 그때 불러온다. 여러 재료가 같은 DLL을 쓰면 한 번만 불러온다.
    • 단면: 다른 재료와 같이 *Section의 재료 이름으로 지정한다. 셸 단면(*Section, Type=Shell)에도 쓸 수 있다. 보 단면의 셀 재료로는 쓸 수 없다.
    • hfStudio: 재료 편집 창에서 유형 User를 고르고 데이터라인을 텍스트로 입력한다. 저장하면 입력한 데이터라인을 그대로 다시 쓴다. hfStudio는 DLL을 불러오지 않는다.

    2.3 Thread 지정

    Hyfeast는 요소 계산을 여러 스레드로 나눠 병렬로 한다(hfAnalyzer -n의 스레드 수). 그래서 서로 다른 적분점에 대한 플러그인 호출이 동시에 일어난다. Hyfeast가 플러그인에 넘기는 버퍼는 호출마다 따로 만들고 적분점별 상태도 따로 저장하므로, 동시 호출에서 값이 섞일 수 있는 곳은 플러그인 내부의 변수뿐이다.

    설정 동작
    Thread=Yes (default) 같은 DLL을 쓰는 재료가 모두 Yes이면 플러그인을 여러 스레드에서 동시에 부른다.
    Thread=No 같은 DLL을 쓰는 모든 재료의 호출을 한 번에 하나씩 차례로 실행한다. 다른 DLL의 호출과 나머지 요소 계산은 계속 병렬로 한다.

    플러그인이 다음 중 하나에 해당하면 Thread=No를 지정한다.

    플러그인 내부 동시에 부르면 생기는 문제
    COMMON 블록, SAVE 변수, 값을 바꾸는 DATA 초기화 변수, C의 static·전역 변수에 계산 중간값을 둔다 한 적분점이 쓰던 값을 다른 적분점이 덮어써 결과가 틀어진다
    첫 호출 때 파일이나 표를 읽어 SAVE 변수에 두는 "최초 1회 초기화"를 한다 여러 스레드가 동시에 초기화해 표가 깨지거나 중복으로 읽는다
    파일이나 화면에 디버그 출력을 쓴다 여러 호출의 출력 줄이 섞인다
    Fortran을 /recursive 없이 직접 빌드했다 컴파일러가 지역 배열을 정적 메모리에 둘 수 있어 스레드끼리 값을 망가뜨린다(build_umat.cmd는 /recursive를 지정한다)
    스레드에 안전하지 않은 외부 라이브러리를 부른다 라이브러리에 따라 오동작한다

    주의할 점:

    • Thread=No는 동시 접근만 막는다. 공유 변수에 적분점별 이력을 저장하는 방식은 순서대로 불러도 틀리다. 적분점별 값은 STATEV에 둔다.
    • Thread=No이면 같은 DLL을 쓰는 요소가 많을수록 해석이 느려진다. 플러그인을 고칠 수 있다면 공유 변수를 없애고 모든 재료를 Thread=Yes로 쓰는 편이 낫다.
    • 모델 전체를 스레드 하나로 돌려도(hfAnalyzer -n 1) 같은 효과가 있지만, 모든 요소 계산이 직렬이 되어 더 느리다.
    • Abaqus도 UMAT를 병렬 스레드로 부른다. 위와 같은 UMAT는 Abaqus에서도 사용자가 잠금(MutexLock)을 소스에 넣어야 하며, Thread=No는 소스를 고치지 않고 Hyfeast가 그 잠금을 대신 거는 것이다.
    • 판단이 어려우면 같은 모델을 -n 1과 여러 스레드로 각각 해석해 결과를 비교한다. 결과가 다르면 Thread=No가 필요하다. 결과가 같아도 안전이 보장되지는 않으므로(값이 섞이는 일은 가끔만 생길 수 있다), 최종 판단은 소스에서 위 항목을 확인해서 한다.

    2.4 Abaqus 입력과의 대응

    Abaqus Hyfeast (첫 데이터라인)
    *MATERIAL, NAME=steel *Material, Type=User, Name=steel
    UMAT 소스(umat.for) build_umat.cmd abaqus umat.dll umat.for로 만든 DLL을 library에 지정
    *USER MATERIAL, CONSTANTS=8 NProps=8
    *USER MATERIAL, UNSYMM Unsymm=Yes
    *DEPVAR 13 NState=13
    *DENSITY Density=...
    *USER MATERIAL 아래 값 줄 둘째 데이터라인부터(PROPS)

    2.5 Example

    # C plugin with E and nu
*Material, Type=User, Name=steelElastic
 plugins/hfUmatElasticC.dll, Density=7.85e-9
 200000., 0.3

# Abaqus UMAT built with the bridge: 13 state variables, 8 constants
*Material, Type=User, Name=steel
 umat\umatmst3.dll, NState=13, NProps=8, Density=7.85e-9
 200000., 0.3, 300., 0.
 400., 0.1, 450., 0.5

# UMAT with an unsymmetric tangent that keeps global state
*Material, Type=User, Name=concreteDP
 "D:\My Plugins\ConcreteDP.dll", NState=24, NProps=11, Unsymm=Yes, Thread=No
 30000., 0.2, 30., 3.0, 0.1, 1.16, 0.667
 35., 0.0015, 0.05, 0.9

*Section, Type=Solid, Name=Block
