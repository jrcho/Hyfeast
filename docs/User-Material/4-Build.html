    4 플러그인 빌드

    플러그인은 64비트 Windows DLL 파일이다. 작성한 소스 파일(C 또는 Fortran)을 컴파일러로 빌드하면 DLL이 만들어지고, 그 DLL 경로를 *Material, Type=User의 첫 데이터라인에 적는다.

    4.1 준비

    필요한 프로그램
    작성 방법 필요한 프로그램
    C, C++ Visual Studio 2019 이상("C++를 사용한 데스크톱 개발" 설치, 권장) 또는 Windows x64용 MinGW-w64 GCC
    Native Fortran, Abaqus UMAT Intel oneAPI Fortran 컴파일러(ifx)와 호환되는 Visual Studio 2019 이상(위와 같은 C++ 구성 요소 설치)

    C/C++ 플러그인은 MinGW-w64의 GCC로도 빌드할 수 있다. GCC는 8 이상을 권장하며, Windows x64 DLL을 만드는 도구를 사용한다. 이 문서의 기본 빌드 절차와 예제 build.bat은 Visual Studio를 기준으로 하므로 Visual Studio 2019 이상을 추천한다.

    Visual Studio 2019 이상이 이미 설치되어 있고 "C++를 사용한 데스크톱 개발" 구성 요소가 포함되어 있으면 그대로 사용한다. C++ 구성 요소가 없으면 Visual Studio Installer의 "수정"에서 추가한다. 이 구성 요소에는 C/C++ 컴파일러와 Windows SDK가 포함된다(Microsoft 설치 안내).

    Fortran으로 작성할 때는 Intel oneAPI Fortran 컴파일러도 설치한다. 사용하는 ifx 버전이 설치된 Visual Studio를 지원하는지는 Intel 호환표에서 확인한다.

    Visual Studio가 없는 컴퓨터에서 명령행 빌드만 하려면, 별도 Build Tools 설치 프로그램에서 "C++를 사용한 데스크톱 개발"을 선택해 설치할 수 있다. 이 경우에도 x64 빌드 도구와 Windows SDK를 포함하고, Fortran은 사용하는 ifx와 호환되는 버전을 선택한다(Build Tools 설치 안내).

    이 장의 예에서 쓰는 폴더

    이 장의 배포 폴더 예시는 D:\Apps\Hyfeast-v1.0.0이다. Bin에는 실행 파일이, Examples\UMAT에는 사용자 재료 예제가 있다. 직접 작성할 재료의 소스와 DLL은 작업 폴더 D:\MyUMAT에 둔다. 아래 명령의 배포 폴더 경로는 실제 압축 해제 위치와 버전 이름으로, 작업 폴더 경로는 자기 작업 위치로 바꿔 쓴다.

    폴더 예로 쓰는 경로 내용
    배포 폴더 D:\Apps\Hyfeast-v1.0.0 ZIP을 풀어 Bin, Examples, HyfeastCmd.bat이 있는 폴더
    개발 키트 폴더 D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial 헤더, Fortran 템플릿, Abaqus 브리지, build_umat.cmd, 예제 소스(1.3절)
    작업 폴더 D:\MyUMAT 직접 작성한 재료 소스를 두고 DLL을 만드는 폴더

    경로에 공백이 있으면(예: D:\My Work\UMAT) 명령에서 그 경로를 큰따옴표로 감싼다.

    명령 창 열기

    빌드는 명령 창에서 한다.

    1. Windows 시작 메뉴에서 설치한 Visual Studio 또는 Build Tools의 x64 개발자 명령 프롬프트를 연다. 창 이름은 설치 버전에 따라 다르며, x64 Native Tools Command Prompt for VS 2022는 한 예이다. 이 창에는 C 컴파일러(cl), 링커, Windows SDK를 x64용으로 쓸 수 있게 환경이 설정되어 있다. Fortran도 이 창에서 빌드할 수 있다. 설치 경로를 자동으로 찾을 수 있는 환경에서는 일반 명령 프롬프트(cmd)에서도 build_umat.cmd를 실행할 수 있다(4.5절).
    2. 작업 폴더로 이동한다.
    cd /d D:\MyUMAT

    이후 명령은 모두 이 창에서 입력한다.

    4.2 C 플러그인

    1. 예제 소스 D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\NativeElasticC\hfUmatElasticC.c를 작업 폴더에 복사하고 이름을 바꾼다(예: D:\MyUMAT\mymat.c).
    2. 파일을 열어 함수 hf_umat_v1의 본문을 자기 재료 모델로 고친다. 인자 목록과 hf_umat_abi_version 함수는 그대로 둔다(3장).
    #include "hfUserMaterialAPI.h"

HF_UMAT_EXPORT void hf_umat_v1(double* stress, double* statev, double* ddsdde, /* ... 37 arguments ... */
                               const hf_int* jstep, const hf_int* kinc)
{
  const int n = *ntens;
  /* fill ddsdde[i + j*n] and update stress[i], statev[k] */
}

HF_UMAT_EXPORT hf_int hf_umat_abi_version(void) { return HF_UMAT_ABI_VERSION; }
    1. 4.1절에서 연 x64 개발자 명령 프롬프트에서 다음을 입력한다.
    cd /d D:\MyUMAT
cl /nologo /O2 /LD /I"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\include" mymat.c /Fe"mymat.dll"
    옵션 뜻
    /LD DLL을 만든다
    /O2 최적화한다
    /I"...\include" 헤더 hfUserMaterialAPI.h가 있는 폴더
    /Fe"mymat.dll" 만들 DLL 파일 이름
    1. 작업 폴더에 mymat.dll이 생긴다. 함께 생기는 mymat.obj, mymat.lib, mymat.exp는 해석에 필요 없다.

    C++로 작성해도 된다. 이때도 헤더를 포함하면 함수 이름이 C 이름 그대로 내보내진다. 함수 밖으로 예외가 나가지 않게 한다.

    MinGW-w64 GCC를 사용한다면 gcc를 실행할 수 있는 명령 창에서 다음과 같이 빌드한다. -shared는 DLL을 만들고, -static-libgcc는 GCC 지원 라이브러리를 정적으로 링크한다.

    cd /d D:\MyUMAT
gcc -std=c99 -O2 -shared -static-libgcc -I"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\include" mymat.c -o mymat.dll

    C++ 소스는 g++로 빌드한다. C++17을 사용할 때는 -std=c++17을 지정하고, C++ 표준 라이브러리도 정적으로 링크하려면 -static-libstdc++를 추가한다. 플러그인이 별도 DLL에 의존한다면 그 DLL도 함께 배포한다.

    4.3 Native Fortran 플러그인

    1. 템플릿 D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\fortran\hf_umat_template.f90을 작업 폴더에 복사하고 이름을 바꾼다(예: D:\MyUMAT\mymat.f90). 완성된 예는 D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\NativeElasticFortran\hfUmatElasticF.f90이다.
    2. 선언부는 그대로 두고 ! ... user material law ... 자리에 재료 모델을 작성한다. 색인은 Abaqus와 같이 1부터다.
    3. 명령 창에서 다음을 입력한다.
    cd /d D:\MyUMAT
"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native mymat.dll mymat.f90

    소스 파일이 여러 개이면 뒤에 이어 적는다.

    "D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native mymat.dll mymat.f90 tools.f90
    1. 끝에 build_umat: created D:\MyUMAT\mymat.dll이 나오면 성공이다.

    4.4 Abaqus UMAT

    Abaqus에서 쓰던 SUBROUTINE UMAT 소스를 고치지 않고 빌드한다.

    1. UMAT 소스(예: umat.for)를 작업 폴더 D:\MyUMAT에 둔다. INCLUDE 'ABA_PARAM.INC'는 그대로 둔다.
    2. 명령 창에서 다음을 입력한다.
    cd /d D:\MyUMAT
"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" abaqus umat.dll umat.for
    1. 끝에 build_umat: created D:\MyUMAT\umat.dll이 나오면 성공이다.

    abaqus를 지정하면 build_umat.cmd가 다음 두 파일을 자동으로 함께 빌드한다. 사용자가 복사할 필요는 없다.

    • D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\abaqus\hfAbaqusUmatBridge.f90: Hyfeast와 원본 UMAT 사이를 잇는 브리지. hf_umat_v1과 hf_umat_abi_version을 내보내고, CMNAME을 공백으로 채운 CHARACTER*80으로 바꿔 원본 UMAT를 부른다.
    • D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\abaqus\ABA_PARAM.INC: UMAT의 INCLUDE 'ABA_PARAM.INC'가 찾는 파일(IMPLICIT REAL*8(A-H,O-Z)).

    조건:

    • 자체 완결형 UMAT여야 한다. Abaqus 유틸리티 루틴(SINV, SPRINC, ROTSIG, XIT 등)을 부르면 빌드 마지막 단계에서 실패한다.
    • DLL 하나에는 재료 하나(hf_umat_v1 하나)만 넣는다. Native Fortran 재료와 Abaqus UMAT를 한 DLL에 함께 넣지 않는다.
    • 스칼라 KSTEP으로 선언한 구식 UMAT도 그대로 동작한다.
    • 예제: D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\AbaqusElasticUMAT\umat_elastic.for(탄성), D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\AbaqusPlasticUMAT\umat_vonmises.for(von Mises 소성).

    4.5 build_umat.cmd가 하는 일

    "D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native|abaqus 만들DLL이름 소스파일 [소스파일 ...]
    • 컴파일러 찾기: Intel Fortran 환경이 설정되어 있지 않으면 설치된 oneAPI의 환경 설정을 자동으로 부른다(IFX_COMPILER26 환경 변수가 있으면 그 경로, 없으면 C:\Program Files (x86)\Intel\oneAPI\setvars.bat). Microsoft 링크 도구도 찾지 못하면 설치된 Visual Studio를 찾아 설정한다. 자동으로 찾을 수 있는 설치 환경에서는 일반 명령 프롬프트에서도 실행할 수 있다. 자동 탐색이 실패하면 설치한 Visual Studio 또는 Build Tools의 x64 개발자 명령 프롬프트에서 Intel oneAPI 환경을 설정한 뒤 실행한다.
    • 컴파일 옵션: /O2 /recursive /threads /libs:static /dll. /recursive는 지역 배열을 스택에 두어 여러 적분점을 동시에 계산해도 안전하게 한다. /libs:static은 Fortran 실행에 필요한 라이브러리를 DLL 안에 넣으므로, 만들어진 DLL 하나만 옮기면 된다.
    • 만들어지는 파일: mymat.dll(해석에 쓰는 파일), mymat.lib, mymat.exp, 폴더 mymat.dll.build(중간 파일). 해석에는 mymat.dll만 필요하다.

    4.6 만든 DLL 쓰기

    *Material, Type=User의 첫 데이터라인에 DLL 경로를 적는다. 절대 경로가 가장 확실하다.

    *Material, Type=User, Name=myMaterial
 D:\MyUMAT\mymat.dll, NState=5, NProps=4
 200000., 0.3, 250., 2000.

    DLL을 입력 파일(.inp)과 같은 폴더에 두면 파일 이름만 써도 된다(mymat.dll). 다른 컴퓨터로 옮길 때는 DLL 파일 하나만 함께 옮기면 된다.

    4.7 확인과 오류 대처

    먼저 *TestMaterial로 재료점 응답(S, E, DSDE)을 확인한 뒤 요소 해석을 한다(5.5절).

    빌드할 때 나오는 메시지:

    메시지 원인과 대처
    build_umat: ifx not found. Install Intel oneAPI Fortran or set IFX_COMPILER26. Intel Fortran이 설치되어 있지 않거나 찾지 못함. Intel oneAPI Fortran 컴파일러를 설치한다.
    build_umat: MSVC link.exe not found. Install Visual Studio C++ build tools. MSVC 링크 도구가 없거나 환경이 설정되지 않음. 설치한 ifx와 호환되는 MSVC 빌드 도구·Windows SDK를 설치하고, 해당 설치의 x64 개발자 명령 프롬프트에서 실행한다.
    'cl'은(는) 내부 또는 외부 명령...이 아닙니다 C 컴파일러가 없거나 환경이 설정되지 않음. MSVC 빌드 도구·Windows SDK를 설치하고, 해당 설치의 x64 개발자 명령 프롬프트에서 실행한다.
    링크 오류 LNK2019(확인할 수 없는 외부 기호, unresolved external symbol)에 SINV, XIT 등이 나옴 UMAT가 Abaqus 유틸리티 루틴을 부름. 지원하지 않으므로 그 호출을 직접 구현한 코드로 바꿔야 한다.
    build_umat: compilation failed. 소스에 문법 오류가 있음. 위쪽에 나온 컴파일러 오류 메시지의 줄 번호를 확인한다.

    해석할 때 로그(.log)에 나오는 메시지:

    로그 메시지 원인과 대처
    User material "name": cannot load path ... (code 126) DLL 또는 DLL이 필요로 하는 다른 DLL을 찾지 못함. 첫 데이터라인의 경로를 확인한다. 필요한 다른 DLL은 플러그인 DLL과 같은 폴더에 둔다.
    hf_umat_abi_version is not exported by ... 함수를 내보내지 않음. C는 HF_UMAT_EXPORT, Fortran은 !DEC$ ATTRIBUTES DLLEXPORT 줄이 빠졌는지 확인한다.
    symbol is not exported by ... hf_umat_v1(또는 첫 데이터라인의 symbol)을 내보내지 않았거나 이름이 다름.
    ABI version n of ... does not match 1 hf_umat_abi_version이 1을 반환하지 않음.
    Invalid syntax (첫 데이터라인) 알 수 없는 키, 같은 키를 두 번 씀, 값이 없는 키(NState=), library 누락.
    Invalid value in user material NState가 음수, NProps가 1보다 작음, Density가 음수, Unsymm·Thread가 Yes나 No가 아님.
    Invalid PROPS value in user material 둘째 줄 이후에 숫자가 아닌 값이나 빈 값이 있음.
    NProps is n but m PROPS values are given PROPS 값 개수가 NProps와 다름.
    User material name must be at most 80 characters 재료 이름이 80자를 넘음.
    PROPS cannot be converted between unit systems 모델과 다른 UnitSystem의 파일에서 사용자 재료를 읽음. PROPS를 모델 단위계로 바꿔 같은 단위계 파일에 둔다.
    User material "name" returned non-finite values 플러그인이 NaN이나 무한대를 돌려줌. 증분을 줄여 다시 시도하며, 계속되면 해석이 멈춘다.
    Invalid cell material 보 단면 셀에 사용자 재료를 지정함(1축 조건 미지원).
    Laminar condition not supported, Uniaxial condition not supported 등 사용자 재료가 지원하지 않는 조건(적층판, 1축 요소, interface 요소)에 지정됨.
