    4 Commands Manual

    4.1 General Information

    The input files used in hfSectAnalyzer/hf2DStudio are text files with blocks containing keywords, similar to those used in hfAnalyzer/hfStudio. The # character denotes a comment, and anything after it is ignored. Blank lines are also ignored. Other than the name following the Name keyword, the input is not case-sensitive. The input file extension is .hf2d.

    Keywords used include *Environment, *Function, *Material, *Geometry, *Section, *SectionStop, *SectionSignal, *SectionAnalysis, and more. Among these, *Function, *Material, and *Section are commands shared with hfAnalyzer, while the rest are commands specific to hfSectAnalyzer/hf2DStudio.

    Three keywords are section-analysis only: *SectionStop, *SectionSignal, and *SectionAnalysis. The others (*Environment, *Function, *Material, *Geometry, *Section) are used just the same in hf2DStudio's 2D finite element modeling work — in that case the geometry and mesh are built without a *SectionAnalysis, and the result is extracted as hfAnalyzer input (see Overview 1.3).

    *Environment, Type=UnitSystem
 force-length-time-temperature

*Function, TYPE=type, Name=name
...

*Material, TYPE=UGeneric, Name=name
...

*Geometry, Name=name[, Taper=Group]
 ...

*Section, TYPE=Beam, Name=name[, Taper=Group]
 *CellMeshPoint
  ...
 *Cell, TYPE=Mesh


*SectionStop
  material, min_strain, max_strain  
  ...

*SectionSignal
  material, strain, msg
  ...

*SectionAnalysis, Name=name, Section=section,Left|Right Ref=angle,yp,zp, Output=Preselect|All
 *SectionStep, ExtLoad=a,b,EK|EM|NK|NM, Inc=inc
  InitialStress|Stress, cellId, value
  ...
 *SectionStep, ...
  ...
 *SectionStepPM, MaxDeform=maxAxial,maxKappa, Inc=1000, PMPoints=50

*SectionAnalysis, Name=name, Section=section
...

    The input file extension is not mandatory, but .hf2d is generally used. Once analysis is performed, a log file and an .xlsx file are generated. The log file displays the calculation progress along with the computed section properties. The .xlsx file stores the results of nonlinear section analysis if *SectionAnalysis is present. For example, analyzing RCColumn.hf2d will result in RCColumn.xlsx containing the nonlinear section analysis results, and the process can be reviewed in the RCColumn.log file.

    4.2 *Environment, TYPE=UnitSystem

    This specifies the unit system. If this command is not present, it indicates that no units are used. The following units are available:

    • force: N, kN, kgf, tonf, lbf, kip
    • length: m, cm, mm, km, in, ft, yd, mi
    • time: s, min, hr, day
    • temperature: K, C, F

    hfSectAnalyzer and hf2DStudio use the same 4-field global *Environment, TYPE=UnitSystem syntax as hfAnalyzer and hfStudio.

    4.3 *Function

    Defines functions required for material model definitions. Among the various functions defined in hfAnalyzer, only the following types can be used:

    *Function, TYPE=Multilinear/ParabolaCEnv/HognestadCEnv/EC2CEnv/MPPCEnv/MaekawaTEnv/ConcreteTime

    For detailed input, refer to the shared *Function command manual. Concrete envelope functions can use concrete material DB items, but the allowed standards depend on the function type. ParabolaCEnv is section-analysis input and accepts only KDS-2026-C<fck> and EC2-2004-C<fck>; it may include alpha before ToDirectForm. HognestadCEnv accepts KDS-2026-C<fck>, ACI318-2025-C<fck>, and EC2-2004-C<fck>. EC2CEnv accepts KDS-2026-C<fck> and EC2-2004-C<fck>. MPPCEnv and MaekawaTEnv accept KDS-2026-C<fck>, ACI318-2025-C<fck>, and EC2-2004-C<fck>. DB function input uses the current global unit system and does not allow a local UnitSystem=... keyword. HognestadCEnv, EC2CEnv, and MPPCEnv may include EciCurve before ToDirectForm. ConcreteTime supports both user-defined function references and EC2/KDS/ACI standard datalines. The user-defined form does not require a global UnitSystem, but standard datalines require the current global UnitSystem and do not allow a local UnitSystem=... keyword.

    4.4 *Material

    Defines a uniaxial material model. Among the various material models defined in hfAnalyzer, only the following types can be used. Properties such as Poisson's ratio, density, and thermal expansion coefficient are ignored.

    *Material, TYPE=IsoElasticity/vonMises/UGeneric/USteel

    For detailed input, refer to the shared *Material command manual. UGeneric does not take a concrete DB item directly in the material data lines. Define the concrete compression and tension envelope functions first, then reference those function names from UGeneric. Compression and tension envelopes may have different initial slopes; UGeneric uses each referenced function as entered.

    4.5 *Geometry

    *Geometry is an editable top-level geometry block written as *Geometry, Name=<name>. In a .hf2d input file, it is paired with *Section, TYPE=Beam, Name=<same-name> through the shared name. The paired *Geometry and *Section are separate top-level blocks; do not nest *Geometry inside *Section. hf2DStudio uses it as the source 2D section sketch for drawing, face/rebar editing, and mesh generation. hfSectAnalyzer reads the same .hf2d file but ignores this block during analysis, so the actual analysis still depends on the generated *CellMeshPoint and *Cell data.

    The *Geometry command line carries the geometry name and optional Taper=Group flag, but no direct data lines. In linked .hf2d files, the same-name *Section, TYPE=Beam block must use the same taper state; use Taper=Group on both blocks for tapered hf2DStudio geometry and omit it from both blocks for prismatic geometry. The geometry itself is described through nested blocks such as *Point, *Curve, *Face, *FaceHint, and *Rebar. *CellMeshPoint and *Cell are not geometry subcommands; after meshing in hf2DStudio, they belong under the paired *Section, TYPE=Beam block. Depending on the current mesh order and mesher path, the resulting *Cell, TYPE=Mesh connectivity can be T3, Q4, T6, or Q8.

    *Geometry, Name=RectRC
 *Point
  ...
 *Curve
  ...
 *Face, 1, conc
  ...
 *FaceHint, 1, 11, 12, 13, 14
 *Face, 2, conc
  ...
 *FaceHint, 2, 21, 22, 23, 24
 ...
 *Rebar, 1, rebar, 25
  ...
 *Rebar, 2, rebar, 25
  ...

*Section, TYPE=Beam, Name=RectRC
 *CellMeshPoint
  ...
 *Cell, TYPE=Mesh
  ...

    In practice, read this block as one *Point block and one *Curve block followed by as many *Face, *FaceHint, and *Rebar blocks as needed. *Point defines geometry points, *Curve defines the boundary curves, *Face defines closed regions and materials, *FaceHint optionally adds four quad-mesh corner hints to a corresponding face, and *Rebar defines reinforcing-bar groups based on geometry points. For taper sections, the left and right coordinates stay linked through the same geometry point entry. After meshing in hf2DStudio, the final analysis section is written as *CellMeshPoint and *Cell.

    The nested blocks and their meaning are:

    4.5.1 *Point

    *Point
 id, y, z {, y, z}  
 ...

    One point per data line. Point IDs must be unique inside the *Geometry block. For taper sections, one line stores the left and right coordinates of the same point so the linked geometry remains consistent. The trailing y, z pair is defined only for tapered sections.

    4.5.2 *Curve

    *Curve
 id, Line, seed, startPoint, endPoint
 id, Arc, seed, startPoint, middlePoint, endPoint
 id, Bezier, seed, point0, point1, point2[, w1]
 id, Bezier, seed, point0, point1, point2, point3[, w1, w2]
 id, Spline, seed, point1, point2, ..., pointN
    seed is the mesh subdivision count used along the curve. Line uses 2 point IDs, Arc uses 3 point IDs (start, mid, end), quadratic Bezier uses 3 point IDs, cubic Bezier uses 4 point IDs, and Spline uses 2 or more point IDs. Arc requires three distinct non-collinear point IDs. Rational bezier curves use the same Bezier keyword with one optional inner weight for degree 2 or two optional inner weights for degree 3. For a 3-point section Bezier, omitting w1 keeps the legacy section-curve interpretation (w1 = 1/sqrt(2)). If you want a pure quadratic bezier, write w1 = 1.0 explicitly. When one weight is present, write it as a real-number token such as 1.0 or 0.70710678; a bare integer token is interpreted as the fourth point ID of a cubic bezier. For a 4-point Bezier, omitted weights are treated as unit weights. All referenced points must already be defined in *Point.

    4.5.3 *Face

    *Face, faceId, material
 +curve1, +curve2, -curve3, ...
 [additional loop lines if needed]
    The command line defines the face ID and material name. Each following data line defines one closed loop with signed curve IDs. + uses the stored curve direction and - reverses it. Additional loop lines can be used for inner holes.

    4.5.4 *FaceHint

    *FaceHint, faceId, p1, p2, p3, p4
    Defines four optional quad-mesh corner hints for an already defined face. The command is keyed by faceId, so it is an independent geometry command rather than a sub-line of *Face, even though it is usually written right after the matching face for readability. p1..p4 must be four distinct point IDs on the face's outer-loop join points. When TFI meshing is enabled, the mesher uses these hints before automatic corner detection to guide the four corners of the TFI patch. Linear mesh generation produces Q4 elements from that patch, while quadratic mesh generation produces Q8 elements.

    4.5.5 *Rebar

    *Rebar, rebarId, material, diameter[, diameterRight]
 pointId1, pointId2, ...
 [additional point lines if needed]
    The command line defines the rebar group ID, material name, and bar diameter. Each following data line lists the geometry point IDs where rebars are placed. For taper sections, diameterRight can also be given.

    • Count rules Only one *Point block and one *Curve block are allowed in one *Geometry block. *Face, *FaceHint, and *Rebar blocks may appear multiple times.

    4.6 *Section, TYPE=Beam

    Among the various section types defined in hfAnalyzer, the Beam type can be used here. Related subcommands include *CellMeshPoint and *Cell.

    For meshed sections, hf2DStudio now writes the direct mesh connectivity as generated. In other words, the *Cell, TYPE=Mesh block is not restricted to linear T3/Q4 cells. The same section block can contain T3, Q4, T6, or Q8 cells that share one *CellMeshPoint table.

    4.6.1 *CellMeshPoint

    *CellMeshPoint
 pointId, y, z {, y, z}
 ...

    The trailing y, z pair is defined only for tapered sections.

    4.6.2 *Cell

    These commands are the same as in hfAnalyzer, but the available *Cell types are as follows.

    *Cell, TYPE=Point/*Cell, TYPE=Point,Circle
*Cell, TYPE=Layer/*Cell, TYPE=Layer,Circle,/*Cell, TYPE=Layer,Stack
*Cell, TYPE=H/T/C/L/2C/2L/HR[-YUp]
*Cell, TYPE=Mesh/*Cell, TYPE=Mesh,Circle/*Cell, TYPE=Mesh,Rectangle
*Cell, TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp]

    TYPE=H/T/C/L/2C/2L/HR[-YUp] defines a direct standard steel shape cell, is treated as a ShapeSection, and can use only elastic material (IsoElasticity). TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp] creates a real material point mesh from the same standard shape data, is treated as a MeshedSection, and can use elastic or inelastic material like a normal Mesh cell. These standard-shape dimensions follow the hf2DStudio template-mesh convention. HR uses H, B, t, r; if r=0, both inner and outer corners are generated as sharp corners, and if r>0, the outer corner radius is r + t. The other standard shapes include only the B2, tf2, c, and r1 through r4 fields meaningful for that shape. Add -YUp to the shape token, for example H-YUp or Mesh,H-YUp, when the section height should follow the local y-direction. For the TYPE=Mesh,H/T/C/L/2C/2L/HR[-YUp] generation form, ToDirectForm can be appended to the first data line to save the generated mesh as normal *CellMeshPoint and *Cell, TYPE=Mesh data.

    When TYPE=Mesh is used, each mesh-cell data line may reference 3, 4, 6, or 8 point IDs depending on the generated section mesh. The standard-shape template mesh may contain Q8 rectangular cells, T6 quarter-fillet cells, and HR annular-corner Q8 cells when r>0. T3/T6 cells use triangle ordering with corner nodes first and midside nodes after them. Q4/Q8 cells use quadrilateral ordering with corner nodes first and edge midside nodes after them. hf2DStudio preserves that connectivity when exporting the section block.

    Section DB references are written as DB, item in place of the numeric geometry data line. Tapered sections may use another DB reference on the second data line. AISC16 items use AISC designation prefixes such as W/M/S/HP, WT/MT/ST, C/MC, L, 2L, HSS, and Pipe; KSD3502-2022 items use Hyfeast-oriented prefixes such as H-, T-, C-, 2C-, L-, and 2L-. For example, H items use the H-HxBxtwxtf form. Round AISC16 HSS and PIPE items use Circle; rectangular and square HSS items use HR or Mesh,HR. Standard-shape DB references are preserved when saved or formatted unless a generated mesh cell uses ToDirectForm; Circle and Mesh,Circle DB references are saved as numeric circle data.

    4.7 *SectionStop

    Specifies the strain at which the section analysis should stop for a particular material, if necessary.

    4.8 *SectionSignal

    Specifies messages to output during section analysis for a particular material.

    4.9 *SectionAnalysis

    Specifies the section analysis. Subcommands include *SectionStep and *SectionStepPM. *SectionStep specifies the section analysis steps, and *SectionStepPM specifies the analysis steps to calculate the PM diagram.

    *SectionStop includes data lines where you input the material, minimum strain (min_strain), and maximum strain (max_strain) at which the analysis should stop. *SectionSignal includes the material, strain condition (strain) at which to output the message, and the output message (msg). These two commands are optional. The following is an example:

    *SectionStop
 conc,-0.005,
 rebar,-0.08,0.08

*SectionSignal
 conc, 0.0001042, "Concrete Tesile Failure"   
 rebar, 0.002, "Rebar Yield??

    In *SectionAnalysis, Name represents the analysis name and is used as the basis for creating the sheet name in the .xlsx file. After Section=section, Left or Right specifies whether to use the start section or the end section when a tapered section is defined (default is Left). Ref=angle, yp, zp are the reference point and rotation angle (in degrees) (default is 0,0,0). In Output, specifying Preselect outputs stress and strain only at the top and bottom edges of each cell, while All outputs stress and strain at all material points (default is Preselect).

    *SectionStep and *SectionStepPM are subcommands of *SectionAnalysis that specify the section analysis steps. *SectionStep refers to general section analysis specifying section deformations or forces. In ExtLoad, depending on the analysis type EK, EM, NK, NM, you specify the values a and b to be reached. Inc=inc is the number of increments, which is optional and defaults to 1.

    • ExtLoad=a,b,EK: Analyze until axial strain and curvature reach a and b, respectively.
    • ExtLoad=a,b,EM: Analyze until axial strain and moment reach a and b, respectively.
    • ExtLoad=a,b,NK: Analyze until axial force and curvature reach a and b, respectively.
    • ExtLoad=a,b,NM: Analyze until axial force and moment reach a and b, respectively.

    The following example instructs to analyze in 100 increments until the curvature reaches 0.00004 while maintaining the axial force at 0:

    *SectionAnalysis, Name=E1, Section=section
 *SectionStep, ExtLoad=0.,0.00004,NK, Inc=100

    *SectionStep can be specified consecutively, allowing for step-by-step section analysis. The following example applies an axial force up to 10, then varies the curvature while maintaining the axial force until failure:

    *SectionAnalysis, Name=E1, Section=section
 *SectionStep, ExtLoad=10.,0.,NM
 *SectionStep, ExtLoad=10.,0.04,NK, Inc=100   # Assumption : 0.04 is large enough to fail the section

    In the data lines of *SectionStep, you can specify initial stress (InitialStress) or target stress (Stress) for the cells that make up the section, if necessary. InitialStress specifies pretension, and Stress specifies post-tension. cellId is the ID of the cell, and value is the stress value. For example, InitialStress, 2, 1000 means to start the analysis with an initial stress of 1000 in cell 2. Stress, 3, 1000 means that cell 3 should have a stress state of 1000 at the final step of the analysis. Specifying Stress, 1, 0 effectively removes cell 1. The following is an analysis where pretension is applied to cell 2, then axial force is applied, and then curvature is applied until failure:

    *SectionAnalysis, Name=PHC500A-N2 Section=PHC500A
 *SectionStep, ExtLoad=0.,0.,NM, Inc=1
   InitialStress, 2, 994.625  # 0.7*fpu
 *SectionStep, ExtLoad=-1766000,0,NM, Inc=1  
 *SectionStep, ExtLoad=-1766000,0.02/250,NK, Inc=1000

    The results of *SectionStep performed within *SectionAnalysis are saved in the sheet named Name in the .xlsx file. The output file has columns like step number, axial strain and axial force (Ex and Nx), curvature and bending moment (Kz, Mz), strain and stress at the material points of the cells (E.C1.1, S.C1.1, etc.), message (Msg.), and so on:

    step, Ex, Nx, Kz, Mz, E.C1.1, S.C1.1, ..., Msg.
...

    4.10 *SectionStepPM

    *SectionStepPM is a command for analyzing the PM diagram. Internally, section analysis is performed by changing the axial force level. First, it calculates the failure load when only axial force is applied, using maxAxial as the axial strain value to be applied. Therefore, maxAxial should be a sufficiently large value that can cause compressive failure. Based on the axial failure load, failure analysis is performed while lowering the axial force level. pmpoints refers to the points on the PM diagram, i.e., the axial force levels. maxKappa defines the maximum curvature in each failure analysis, so it should be specified as a sufficiently large value to cause failure. Inc is the number of increments used in each failure analysis. The following is an example of performing PM analysis on a reinforced concrete section:

    *SectionAnalysis, Name=RCSec, Section=RCSec
 *SectionStepPM, MaxDeform=-0.005,0.02/250, Inc=1000, PMPoints=50

    You can specify *SectionStepPM only once within *SectionAnalysis, and it can be specified after *SectionStep but must be the final analysis step. The following is an example of performing PM analysis on a pretensioned member:

    *SectionAnalysis, Name=PHC500A Section=PHC500A
 *SectionStep, ExtLoad=0.,0.,NM, Inc=1
   InitialStress, 2, 994.625  # 0.7*fpu
 *SectionStepPM, MaxDeform=-0.005,0.02/250, Inc=1000, PMPoints=50

    *SectionStepPM performs as many section analyses as the number of PMPoints. The results of each section analysis are saved in sheets named Name-PM@plevel, and the deformation/forces at failure points are summarized and saved in the sheet Name-PM. In the above example, since PMPoints=50, the following files are generated:

    • PHC500A-PM@0: when the axial force level is 0
    • PHC500A-PM@2: when the axial force level is 2% of the failure axial force
    • ...
    • PHC500A-PM@100: when the axial force level is 100% of the failure axial force (moment is 0)
    • PHC500A-PM: file summarizing the deformation/forces at failure according to axial force levels

    The Name-PM sheet has the following format:

    PuLevel, ISTEP,Increment,E,N,K,M,MsgAtMaxPoint,RunningResultMsg
100,2,550,-0.002808,-8827490.751676,0.000000,-0.000000,,Stop Strain Reached
