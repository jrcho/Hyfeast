    10. Construction

    *Construction defines auxiliary geometric entities used during modelling. Each construction must have a unique name.

    10.1 *Construction

    Define one auxiliary geometric entity.

    *Construction, Type=type, Name=name[, Ref=ucs]
 ...
    Keyword line
    • TYPE=type: Construction type
      • Guide: Non-analysis guide geometry used for display, snapping, picking, intersections, and reference shapes
      • Spline: Independent parametric spline object
    • Name=name: Construction name
    • Ref=ucs: Reference User coordinate system for the input coordinates (optional)

    If Ref=ucs is given, all coordinates in the data lines are interpreted in that User coordinate system and are converted to GCS immediately when the command is read. The converted GCS coordinates are what remain stored in the model. Therefore printFormatted() writes ordinary GCS coordinates and does not print Ref=ucs.

    10.1.1 Construction Geometry Theory

    This section summarizes the geometry used by *Construction. For Type=Guide, one construction can contain Line, Arc, Bezier, and Spline primitives used as modelling aid geometry for display, snapping, picking, intersection calculations, and reference shapes. For Type=Spline, the construction itself is an independent parametric cubic spline object. All listed coordinates are stored in GCS; if Ref=ucs is specified on the keyword line, the input coordinates are first interpreted in that User coordinate system and then converted to GCS during reading. The analysis itself does not use guide geometry directly.

    Arc geometry

    A guide Arc is defined by three 3D points:

    • \(P_0 = (x_0, y_0, z_0)\): start point
    • \(P_m = (x_m, y_m, z_m)\): point that the arc must pass through
    • \(P_1 = (x_1, y_1, z_1)\): end point

    If these three points are distinct and non-collinear, they define a unique plane and a unique circumcircle. Let \(C\) be the center of that circle and let

    \[ r = \| P_0 - C \| \]

    be its radius. In a local orthonormal basis \((e_x, e_y)\) on the arc plane, the circular arc can be written as

    \[ P(t) = C + r \left( \cos \theta(t)\, e_x + \sin \theta(t)\, e_y \right), \qquad 0 \le t \le 1 \]

    with

    \[ \theta(t) = \theta_0 + t \Delta \theta \]

    where \(\theta_0\) is the angle of \(P_0\) about \(C\), and the sweep \(\Delta \theta\) is chosen so the interpolated arc starts at \(P_0\), ends at \(P_1\), and passes through \(P_m\). In other words, the middle point determines which side of the circle and which sweep direction are used.

    If the three points are collinear, nearly coincident, or otherwise degenerate, a valid circular arc cannot be constructed geometrically. Use Arc when you need a true circular reference shape instead of a curve that only approximates a circle.

    Bezier geometry

    A guide Bezier is a parametric curve defined by control points. The supported forms are:

    • quadratic Bezier: 3 control points
    • cubic Bezier: 4 control points
    • rational quadratic/cubic Bezier: the same control points plus optional internal weights

    For a quadratic Bezier with control points \(P_0, P_1, P_2\),

    \[ B(t) = (1-t)^2 P_0 + 2(1-t)t P_1 + t^2 P_2, \qquad 0 \le t \le 1 \]

    For a cubic Bezier with control points \(P_0, P_1, P_2, P_3\),

    \[ B(t) = (1-t)^3 P_0 + 3(1-t)^2 t\, P_1 + 3(1-t)t^2 P_2 + t^3 P_3, \qquad 0 \le t \le 1 \]

    If weights are given, the guide is interpreted as a rational Bezier curve with the general form

    \[ R(t) = \frac{\sum_{i=0}^{n} w_i B_i^{n}(t) P_i}{\sum_{i=0}^{n} w_i B_i^{n}(t)} \]

    The Bernstein basis used in that expression is

    \[ B_i^{n}(t) = \binom{n}{i} (1-t)^{n-i} t^i \]

    where \(n\) is the degree.

    In the Guide syntax, only the internal weights are written explicitly:

    • quadratic rational Bezier: \((w_0, w_1, w_2) = (1, w_1, 1)\)
    • cubic rational Bezier: \((w_0, w_1, w_2, w_3) = (1, w_1, w_2, 1)\)

    With that convention, the explicit quadratic rational Bezier formula becomes

    \[ R_2(t) = \frac{(1-t)^2 P_0 + 2 w_1 (1-t)t\, P_1 + t^2 P_2}{(1-t)^2 + 2 w_1 (1-t)t + t^2}, \qquad 0 \le t \le 1 \]

    and the explicit cubic rational Bezier formula becomes

    \[ R_3(t) = \frac{(1-t)^3 P_0 + 3 w_1 (1-t)^2 t\, P_1 + 3 w_2 (1-t)t^2 P_2 + t^3 P_3}{(1-t)^3 + 3 w_1 (1-t)^2 t + 3 w_2 (1-t)t^2 + t^3}, \qquad 0 \le t \le 1 \]

    If the optional weights are omitted, or if the specified internal weights are all \(1.0\), the rational form reduces exactly to the ordinary polynomial Bezier curve. Rational Bezier curves are useful when you want tighter geometric control or conic-like shapes. In particular, a quadratic rational Bezier can represent a true circular arc. For example, with a suitable middle control point, \(w_1 = 1/\sqrt{2} = \sqrt{2}/2\) gives an exact quarter-circle arc in a plane.

    Spline geometry

    The Spline primitive inside *Construction, Type=Guide and the independent *Construction, Type=Spline are both defined by two or more sampling points \(P_0, \dots, P_m\). In the current implementation, these points are interpreted as a parametric cubic spline

    \[ S(t) = (x(t), y(t), z(t)) \]

    that interpolates the given samples.

    The parameter values are generated from normalized accumulated chord length:

    \[ t_0 = 0, \qquad t_i = \frac{\sum_{k=1}^{i} \| P_k - P_{k-1} \|}{\sum_{k=1}^{m} \| P_k - P_{k-1} \|}, \qquad i = 1, \dots, m \]

    On each interval \([t_i, t_{i+1}]\), each coordinate is represented by a cubic polynomial:

    \[ x(t) = a_i^x t^3 + b_i^x t^2 + c_i^x t + d_i^x \]
    \[ y(t) = a_i^y t^3 + b_i^y t^2 + c_i^y t + d_i^y \]
    \[ z(t) = a_i^z t^3 + b_i^z t^2 + c_i^z t + d_i^z \]

    This spline representation is useful when you need a smooth curve through many sampling points. Unlike Bezier, the shape is controlled by interpolation of the sampling points rather than by a small set of control points. For Type=Guide, the cubic spline is sampled into a polyline for rendering and picking.

    10.1.2 *Construction, Type=Guide

    Define a guide set.

    *Construction, Type=Guide, Name=name[, Ref=ucs]
 Line, x0, y0, z0, x1, y1, z1
 Arc, x0, y0, z0, xm, ym, zm, x1, y1, z1
 Bezier, x0, y0, z0, x1, y1, z1, x2, y2, z2[, w1]
 Bezier, x0, y0, z0, x1, y1, z1, x2, y2, z2, x3, y3, z3[, w1, w2]
 Spline, x0, y0, z0, x1, y1, z1, ...
 ...
    First data line and subsequent data lines
    • Line, x0, y0, z0, x1, y1, z1: One guide line segment [L]
    • Arc, x0, y0, z0, xm, ym, zm, x1, y1, z1: One guide arc defined by start, mid, and end points [L]
    • Bezier, ...: One quadratic or cubic Bezier primitive. If optional weights are given, it is interpreted as a rational Bezier.
    • Spline, ...: One guide spline primitive defined by two or more sampling points and interpreted as a parametric cubic spline [L]

    Guide is not used by the analysis functionality. It is intended as modelling aid geometry for display, snapping, picking, intersection calculations, and reference shapes needed for visualization. See Construction Geometry Theory above for the geometric meaning of Arc, Bezier, and Spline. If Ref=ucs is present, the primitive coordinates are interpreted in that User coordinate system only while reading, and the stored guide remains in GCS.

    Example
    *Construction, Type=Guide, Name=deckGuide
 Line, 0, 0, 0, 10, 0, 0
 Line, 0, 5, 0, 10, 5, 0
 Arc, 10, 0, 0, 12, 2, 0, 14, 0, 0
 Bezier, 0, 0, 0, 5, 5, 0, 10, 0, 0
 Bezier, 0, 0, 0, 5, 5, 0, 10, 0, 0, 0.7071067811865476
 Bezier, 0, 0, 0, 3, 4, 0, 7, 4, 0, 10, 0, 0
 Spline, 0, 0, 0, 3, 2, 0, 7, -1, 0, 10, 0, 0

    10.1.3 *Construction, Type=Spline

    Define an independent spline object.

    *Construction, Type=Spline, Name=name[, Ref=ucs]
 x, y, z
 ...
    First data line and subsequent data lines
    • x, y, z: Coordinates of sampling points [L] (required)

    This is an independent named spline object, not a primitive inside a Guide set. It is used to define the shape of embedded line elements and also to define geometry in *Sensor, Type=LineSensor. At least two sampling points must be defined. The spline is constructed as a parametric cubic spline of the form \((x(t), y(t), z(t))\) using the provided sampling points. \(t\) is generated from the accumulated secant length of the given coordinates, and its range is \([0, 1]\). When Ref=ucs is given, the listed sampling points are interpreted in that User coordinate system and converted to GCS immediately during reading.

    Example
    *Construction, Type=Spline, Name=2spanTendon
  0,  0.         , 0.
 13, -0.8        , 0.
 26,  0.19411765 , 0.
 30,  0.5        , 0.
 34,  0.19411765 , 0.
 47, -0.8        , 0.
 60,  0          , 0.
