    13. Step

    Analysis-related commands primarily include *Step and *PostStep. The *Step command specifies the stages for performing the actual analysis, while *PostStep is used to organize and process the analyzed results.

    In the *Step command, you can specify analysis types such as Static, Dynamic, Frequency, and Buckling. By designating a sequence of steps prior to *Step, simulations can be structured into multiple analysis phases. Subcommands within *Step include *Activate and *Inactivate for specifying or altering elements, loads, and constraints, as well as *Solver, *SolutionAlgorithm, *Convergence, *RayleighDamping, and *Modal for setting analysis options, and *InitialCondition and *State for the step start state. For output specifications, commands such as *Output, *Print, *History, and *Check are available.

    When the *Step command is executed, an output step named ResultStep is created in the HDB file (.hdb), where results specified by *Output are stored. *PostStep operates on an existing ResultStep to extract specific results, compute maxima or minima, combine results, and generate a new ResultStep.

    Names used in *Step and *PostStep must be unique.

    Defines an analysis step.

    This categorizes the analysis types as follows:

    ▪ Standard Analysis Steps

    ▪ Static Analysis Steps

    • Standard load-displacement controlled static analysis step

    • Arclength-controlled static analysis step

    • Quasi-static analysis step (time-dependent static analysis)

    ▪ Dynamic Analysis Steps

    ▪ Eigen Analysis Steps

    • Frequency extraction analysis step

    • Response spectrum analysis step

    ▪ Seepage Analysis Step

    • Steady state seepage analysis step

    • Transient seepage analysis step

    The way time is handled depends on the analysis type:

    ▪ Standard Load-Displacement Controlled Static Analysis Step

    The given time represents a pseudo-time, interpreted as a load factor.

    ▪ Arclength-Controlled Static Analysis Step

    The time is normalized to a pseudo-time based on the arclength occurring when the load factor is 1 in a linear response. Thus, applying Arclength control in a linear analysis yields the same time increments as the standard method.

    ▪ Quasi-Static Analysis Step

    A static analysis that considers time dependency without mass effects. The given time is interpreted according to the Static, Quasi row in the time interpretation table below. Time dependency arises in load cases with time functions and in time-dependent material models. To account for time dependency in static analysis, a time-dependent analysis must be performed.

    ▪ Dynamic Analysis Step

    Considers both mass effects and time dependency. The given time is interpreted according to the Dynamic row in the time interpretation table below. Supported time integration methods include Newmark and Hilbert-Hughes-Taylor (HHT) methods, specified in *TimeIntegration. The default integration method is the Newmark method (or average acceleration method) with coefficients \(\gamma=0.5\) and \(\beta=0.25\). When using the HHT method, the default value for \(\alpha\) is -0.05.

    ▪ Steady State Seepage Analysis Step

    The given time represents a pseudo-time, interpreted as a load factor.

    ▪ Transient Seepage Analysis

    The given time is interpreted according to the Seepage, Transient row in the time interpretation table below.

    Time Increment and Output Control

    In *Static, *Dynamic, and *Seepage analyses, the analysis time increment (or pseudo-time increment in Static analysis) can be specified using one of three options: Uniform, Given, or Auto. Meanwhile, the times at which results are written via *Output, *Print, *History, etc., are controlled by OutFreq or OutTime.

    *Step, Type=Static|Dynamic|Seepage,...,  Name=name, PREV=prevStep, NLGeom=ON|OFF
 Uniform, dt, ntime[, TUnit=tUnit], OutFreq=freq
 Given, timeSpec[, TUnit=tUnit], OutFreq=freq|OutTime=timeSpec
 Auto, t0, tmax, dtmin, dtmax, maxInc[, TUnit=tUnit], OutFreq=freq|OutTime=timeSpec
    • Uniform specifies the analysis time using uniform intervals, Given specifies the times explicitly, and Auto uses automatic increment control.
    • OutFreq and OutTime cannot be specified simultaneously. OutTime can be used with Given and Auto.
    • OutFreq=freq outputs results every freq increments, based on the analysis increment.
    • When specified as OutFreq=0, results are output only at the final time.
    • With Given, every OutTime=timeSpec value shall be 0 or one of the specified analysis times. Specify 0 to write the Step-start state.
    • With Auto, OutTime=timeSpec defines output anchors, and analysis increments are adjusted automatically to reach them.
    • With both OutFreq and OutTime, output is always produced at the final time (the last analysis time, or the last successfully converged time even in the case of convergence failure).
    • When Given or OutTime is specified, timeSpec may use a range expression of the form tStart:tEnd:tSpacing. For example, expressions such as Given, 0.5, 2.5:7.5:2.5, 10 are allowed. In this case, 2.5:7.5:2.5 is interpreted as 2.5, 5.0, 7.5.
    • If tEnd in the tStart:tEnd:tSpacing range expression does not exactly match the spacing, time values are generated within the range that does not exceed tEnd. For example, 1:10:2 is interpreted as 1, 3, ..., 9, which is equivalent to substituting 1:9:2.
    • TUnit=tUnit specifies the step time basis. Supported tUnit values are s, min, hr, and day. It is required for Static, Quasi and Seepage, Transient. It cannot be used for other pseudo-time analyses, including Seepage, Steady, or for analyses whose time follows the global UnitSystem time field.
    Time interpretation

    The following table is the central rule for interpreting Uniform, Given, Auto, and OutTime time values.

    Step type Time class Meaning and consistency rule
    Static, Standard/Arclength pseudo-time Load-factor or arc-length progress coordinate. Independent of the global UnitSystem.
    Dynamic physical time in the global UnitSystem, if a global UnitSystem is defined Physical time that shall be consistent with inertia, mass, damping, and acceleration-related quantities.
    Static, Quasi physical time represented by step-defined time, independent of the global UnitSystem Physical time not used in inertia terms, but referenced by time-dependent loads and materials. The time unit is specified by TUnit=tUnit on the first data line.
    Seepage, Steady dimensionless progress coordinate Progress for the load, PTC, or material path. It is not physical time and does not advance rtime.
    Seepage, Transient physical time represented by step-defined time, independent of the global UnitSystem Transient seepage time that shall be consistent with permeability, flux, storage terms, and boundary conditions. The time unit is specified by TUnit=tUnit on the first data line.

    step-defined time means the physical time coordinate defined for a specific analysis step. Its unit is not taken from the time field of the global UnitSystem; it follows the TUnit specified on the first data line of that step. When a Static, Quasi step uses the standard ConcreteTime function, the concrete time variable is day-based, so the step TUnit must also be day.

    Hyfeast distinguishes the time coordinate progressing inside a step, stime, from the physical time that passes across consecutive steps, rtime. Internally, rtime is accumulated in seconds, but input and output use the time unit of the corresponding step. Dynamic steps use the time field of the global UnitSystem; Static, Quasi and Seepage, Transient steps use TUnit. Pseudo-time in Seepage, Steady and Static, Standard/Arclength is only a progress coordinate and does not advance rtime.

    When an element is activated, the current rtime is recorded as that element's birthTime. The element elapsed time ELTIME is not a stored field; it is a derived field computed as:

    \[ \mathrm{ELTIME}=\mathrm{rtime}-\mathrm{birthTime} \]

    The output unit of ELTIME follows the physical time unit of the current step. In pseudo-time steps, rtime does not advance, so ELTIME is output using the last physical-time value. If there has been no previous physical-time step, s is used.

    13.1.3 *Step, Type=Frequency

    Defines a Frequency Analysis Step.

    *Step, Type=Frequency, Name=name[, PREV=prevStep]
 nev
    First dataline
    • nev: requested number of eigenpairs (default 20).

    nev is interpreted differently depending on the *Solver command.

    • If there is no *Solver command, or if Range=cutFreq is specified, nev denotes the requested number of eigenpairs. In this case, the number of computed eigenpairs does not exceed nev.
    • If Range=lowFreq, highFreq[,maxnev] is specified in the *Solver command, nev denotes the requested number of accepted filtered eigenpairs. The solver stops when the accepted count reaches the smaller of nev and maxnev, and the final result count is also capped by that value; that is, maxnev acts as a cap only when it is smaller than nev. If the cap boundary falls inside a multiplicity group of the same eigenvalue, the whole group is preserved, so the result may slightly exceed the cap.

    Algorithm description

    The values entered on a Seepage, Steady data line are not physical time. They are values of the dimensionless progress \(s\), which indicates how far the analysis has advanced toward the target steady-state problem. Path selects the auxiliary problems followed as \(s\) changes. For every path, the auxiliary process ends and the original steady-state problem is recovered at \(s=1\); therefore, the final progress value shall be exactly 1. Do not specify TUnit for Steady. Permeability uses its material TUnit when specified; otherwise it uses the global time unit from *Environment, Type=UnitSystem. Without a global unit system, all quantities with a time dimension must use the same consistent unit $[T]`; the program neither assumes nor converts them to a particular unit such as seconds or minutes.

    The values entered on a Seepage, Transient data line are physical time, and their unit is specified with TUnit. This setting does not redefine the input unit of permeability. Permeability is converted from its material TUnit, or from the global UnitSystem time unit when the material setting is omitted, to the step TUnit.

    The following paths are available for Steady. The default is Material when Path is omitted.

    Path Quantity varied by the common progress \(s\)
    Load Increases the prescribed loads and pressures to their target values according to \(s\). The input material laws are used from the start.
    PTC Applies the full loads, prescribed pressures, and material laws from the start. A diagonal stabilization term is used at intermediate progress points and removed completely at the endpoint.
    Material Applies the full loads and prescribed pressures from the start and changes only the VGM relative permeability from its saturated value to the input material value.

    Omitting the Seepage, Steady data line is equivalent to Auto,1,1,0,1,1000, Path=Material, OutFreq=0. The first attempt solves the original steady-state problem directly at \(s=1\). If it fails and Auto cuts back the progress increment, Material continuation becomes active at \(s<1\).

    At every Steady progress increment, the program checks the flow balance over the entire boundary after the nonlinear equilibrium iterations and the PSF boundary interaction have converged and before accepting the increment. The current increment is accepted only when the relative difference between total inflow and outflow does not exceed the internal tolerance \(10^{-4}\). If the ordinary convergence criteria are met but the flow balance is insufficient, equilibrium iteration continues at the same increment. If the balance cannot be satisfied within the allowed iterations, the increment fails. Auto then reduces the progress increment and retries; Uniform and Given do not perform automatic cutback.

    LScheme stabilizes the storage tangent inside each physical time increment of Seepage, Transient. It is distinct from Path, which selects a steady continuation path, and from Uniform, Given, or Auto, which define the time increments.

    For Solver, Type=Eigen, General, the options Range, Threshold, ZeroEigTol, and Strategy are available. The default is Sweep.

    If a Range or Threshold condition is specified, the solver searches for modes satisfying the condition by increasing the candidate eigenvalue count, nev, step by step. During this process, an internal limit, nevLimit, is automatically set to cap the upper bound of the candidate eigenvalue count. This value is determined by considering the number of active mass degrees of freedom, the available memory, and the solver characteristics together. Therefore, even when filter conditions are used, the computation time and memory usage are controlled so that they do not increase excessively.

    Threshold=EMMR corresponds to a mode-selection strategy based on the cumulative effective modal mass ratio, which is advantageous for securing sufficient modal contribution for a given load pattern. In contrast, Threshold=MPR corresponds to a strategy in which candidate modes are first identified within the frequency band of interest, and then modes are selected based on their relative modal participation within that band. Therefore, the MPR criterion is particularly effective when used together with frequency-band-based selection, and it is more suitable in cases such as unsymmetric systems, where the cumulative value of the generalized EMMR may not increase monotonically. In practice, the search range is managed by using either the EMMR or MPR filter together with the internal nevLimit control. With Strategy=Expansion, reaching nevLimit is treated not as an error but as a normal termination reason (stop reason); with Strategy=Sweep, nevLimit is not a termination condition but only caps the candidate eigenvalue count used in each sweep window.

    In unsymmetric systems, eigenvalues may in general become complex, so restricting eigenvalues based on a specific real-valued interval may not work properly. On the other hand, in symmetric systems, eigenvalues are always real but may still be computed as negative. Even in this case, a simple frequency-range restriction is not always valid. Therefore, for both symmetric and unsymmetric systems, Range-based extraction is reliably valid only in special cases where the eigenvalues are computed as real and nonnegative.

    Algorithm description

    *NonlinearAlgorithm selects the tangent used to compute the correction and the coefficient-matrix update policy. StepCtrl separately controls the step length applied to that correction.

    Coefficient-matrix update

    Picard, Newton, and HNewton rebuild the coefficient matrix at every equilibrium iteration. MNewton forms a Newton tangent at the start of an increment, reuses the matrix and its factorization, and rebuilds them at the interval specified by kernelUpdate. The residual and current state are still recomputed at every iteration. Seepage always rebuilds the matrix at the start of a new increment, a cutback retry, and a new PSF active-set iteration. BFGS and Secant rebuild their base matrix at the kernelUpdate interval and use their respective quasi-Newton updates between rebuilds.

    Static arclength analysis is an exception and rebuilds the coefficient matrix at every iteration regardless of the selected algorithm.

    Picard, Newton, and Hybrid Newton tangents

    For seepage analysis, Picard uses the reference tangent \(\mathbf K_{\mathrm P}\), which omits the pressure derivatives of material properties. Newton and MNewton use the Newton tangent \(\mathbf K_{\mathrm N}\), which includes all available material derivative terms.

    HNewton is Hybrid Newton, which blends the Picard and Newton tangents:

    \[ \mathbf K_{\mathrm H}(r) =(1-r)\mathbf K_{\mathrm P}+r\mathbf K_{\mathrm N}, \qquad 0\le r\le1. \]

    The fixed form HNewton, r requires \(0<r<1\). Use Picard for \(r=0\) and Newton for \(r=1\) so that the selected tangent is explicit.

    The adaptive form HNewton, r0, grow, shrink, tolSwitch adjusts \(r\) from the pressure-correction history. In each PSF active-set equilibrium solve, the first two pressure-correction directions are computed with the r0 tangent. The Picard tangent is used after the second correction has been applied, and that correction defines the reference magnitude. Subsequent corrections use

    \[ q_k = \frac{\lVert \Delta p_k \rVert_\infty}{\max(\lVert \Delta p_2 \rVert_\infty,p_{guard})}. \]

    where \(p_{guard}\) is a small positive internal value that prevents a zero denominator. When \(q_k\) is below tolSwitch and continues to improve, \(r\) increases by grow; otherwise it decreases by shrink. A changed PSF active set resets \(r\) and the reference. In transient seepage, they are also reset at each physical time increment. grow=1, shrink=1 selects direct switching, whereas the recommended values grow=0.2, shrink=0.3 produce a gradual blend. The updated \(r\) is applied to the blended tangent rebuilt at the next equilibrium iteration.

    For Seepage, the default Warmup value of *Convergence is 100 for Picard and 20 for the other nonlinear algorithms.

    Correction step length

    StepCtrl determines the step length \(\eta_i\) applied to the correction \(\delta\mathbf x^i\) computed from the linearized system:

    \[ \mathbf x^{i+1}=\mathbf x^i+\eta_i\,\delta\mathbf x^i. \]

    It does not change the tangent type or the matrix-rebuild interval. None uses \(\eta_i=1\). SchedRelax reduces the step length according to a prescribed iteration schedule. RelaxBack, ArmijoBack, and Bracketed evaluate trial states during the iteration to select an acceptable step length.

    For seepage analysis, Picard and HNewton support None, SchedRelax, and RelaxBack. Newton and MNewton support None, RelaxBack, ArmijoBack, and Bracketed.

    StepCtrl=None explicitly means that no line-search procedure is applied.

    ** Force/Moment criteria

    \[ \left\lVert \mathbf r^i_{g,n+1} \right\rVert_2 \le \max\left(\epsilon_F \left\lVert \mathbf r^1_{g,n+1} \right\rVert_2, R_{min,g}\right) \]

    ** Displacement/Rotation/Pressure correction criteria

    \[ D_{tol,g}^{i+1} = \max\left( \epsilon_{D,g}\left\lVert \Delta \mathbf u^{i+1}_{g,n+1} \right\rVert_\infty, D_{min,g} \right) \]

    \[ D_{tol,g}^{i+1} \leftarrow \min\left(D_{tol,g}^{i+1},D_{max,g}\right) \]
    \[ \left\lVert \delta \mathbf u^i_{g,n+1} \right\rVert_\infty \le D_{tol,g}^{i+1} \]

    The subscript \(g\) denotes a physical-quantity group. \(\Delta\mathbf u^{i+1}_{g,n+1}\) is the increment accumulated from the previously converged solution to the current iterate, and \(\delta\mathbf u^i_{g,n+1}\) is the correction applied in the current iteration. The force criteria use the residual L2 norm, while the correction criteria use the infinity norms of these two increments. If dmax is None, the cap update is not applied.

    The same \(\epsilon_F\) applies to all physical quantities, with the primary tolerance used through iteration 8 and the secondary tolerance from iteration 9. When fmin is specified explicitly, its numeric value is shared by the active residual groups. An omitted default follows the force unit only for XYZ and RXYZ; P, T, and General use a raw value in each residual's native unit. Rotational DOFs use \(R_{min}L_{global}\), where \(L_{global}\) is the median element-edge length. The correction criteria use quantity-specific \(\epsilon_D\), \(D_{min}\), and \(D_{max}\) values. \(D_{min}\) is a floor that prevents an excessively small tolerance, while a positive \(D_{max}\) is a cap that prevents an excessively large tolerance. A dmax value of None disables the cap.

When an iteration counter restarts, as in a steady-seepage active-set interaction, the previous history is discarded and a new warm-up and trend history begin. Normal convergence checks and the maxIter limit remain active during warm-up, while numerical abnormalities are checked independently of warm-up.

    This policy and its defaults are independent of Steady/Transient mode and the StepCtrl type for Seepage. Residual-trend Divergent and Stagnated checks are not applied to Linear analysis. Modal and Frequency behavior is unchanged.

    In the Newmark method, coefficients \(\beta\) and \(\gamma\) are determined based on numerical stability and accuracy. When \(\gamma=1/2\), no numerical damping is introduced, whereas if \(\gamma>1/2\), numerical damping is introduced. Typically, values of \(\gamma=1/2\) and \(1/6 \le \beta \le 1/4\) are chosen. With \(\gamma=1/2\) and \(\beta=1/4\), the acceleration is assumed constant within the time interval, a method known as the average acceleration method. When \(\gamma=1/2\) and \(\beta=1/6\), the acceleration is assumed to vary linearly within the time interval, known as the linear acceleration method. For numerical stability, the following condition must be satisfied:

    \[ \frac{\Delta t}{T_n} <= \frac{1}{\pi \sqrt 2} \frac{1}{\sqrt {\gamma-2\beta}}, ~~ \rm \text{where, } \it T_n \rm \text{ is natural frequency} \]

    Thus, using the average acceleration method ensures unconditional stability, while the linear acceleration method requires satisfying \(\frac{\Delta t}{T_n}\) for stability. In finite element problems involving multiple degrees of freedom, it is challenging to meet this stability condition up to higher modes with shorter natural periods (higher natural frequencies). Consequently, the average acceleration method is generally used for its unconditional stability, even if it sacrifices some precision.

    The Hilbert-Hughes-Taylor (HHT or \(\alpha\)-method) extends the Newmark method by introducing controllable numerical damping while maintaining solution accuracy.     \[ \left[ \begin{matrix} \xi_m \\ \xi_n \\ \end{matrix} \right] = \frac{1}{2} \left[ \begin{matrix} 1/\omega_m & \omega_m\\ 1/\omega_n & \omega_n\\ \end{matrix} \right] \left[ \begin{matrix} \alpha \\ \beta \\ \end{matrix} \right] \]

    In the above, \(\omega_m = 2\pi f_m\) and \(\omega_n = 2\pi f_n\), and the determined values of \(\alpha\) and \(\beta\) are constants in the Rayleigh damping matrix, defined as \(C^R = \alpha M + \beta K\).

    Modal analysis is a special technique for performing dynamic analysis on linear systems.

    1. When specified with *Modal, *RayleighDamping is ignored.
    2. Only the Newmark method is allowed as the integration method with *Modal. If HHT or Frequency is specified as the integration method, an error occurs.
    3. In the uniform form, modes 1 through nmode participate in the modal analysis. In ByIndex and ByFreq, only the selected modes participate. If the requested modes required for the eigen solve cannot be computed through eigenvalue analysis, an error is raised.
    4. *Load, Type=Displacement cannot be applied in modal analysis.
    5. Reaction forces in modal analysis do not consider the effects of modal damping.
    6. Modal analysis can only be applied to linear elsets.
    7. If targetElset is not specified, modal analysis is conducted on the entire model, which must be a linear system.
    8. When targetElset is specified, partial modal analysis is performed only for that element set. In this case, only the specified targetElset is required to satisfy the linearity condition. This feature can be useful in vehicle-bridge interaction analyses where elements become nonlinear due to changes in contact points.
    9. *Solver, Type=Eigen may be specified after *Modal. In that case, the eigen-solver options are used for the modal extraction. If *Solver, Type=Eigen is omitted, the default eigen-solver settings are used.

    The start state of a step is built as follows: (1) the end state of the Prev= step, or the default initial state without Prev=; (2) *InitialCondition; (3) *State; (4) time-0 state evaluation (seepage: water content and saturation from the initial pressure; dynamic: damping force from the initial velocity); (5) the first increment. Two water tables sharing a node are an error; split the region with Nset. Without any P-field initial condition and without Prev=, transient seepage starts from the default \(H=0\) (\(p=-\gamma_w z\)). Steady seepage has no physical initial time, so *InitialCondition is rejected there; use a steady step with Prev= when an equilibrium initial field is needed.

    • BSF, BSE, BST: Cross-sectional force, strain, and temperature for beam elements (including truss/cable elements)
    • SSF, SSE, SST: Cross-sectional force, strain, and temperature for shell elements
    • SF, SE, DF, DE: Cross-sectional force and strain for spring elements, and force and strain for damper sections
    • S: Stress
    • E, EM, EE: Total, mechanical, and elastic strain
    • EP: Plastic strain
    • ENM, ETH: Non-mechanical strain and thermal strain
    • SB: Back stress
    • IEC, IET: Compressive and tensile inelastic strain
    • ECUN, ETUN: Last committed compressive/tensile unloading strain
    • PEEQ, PEEQT, PEEQC: Equivalent plastic strain, and tensile/compressive equivalent plastic strain
    • MTEMP: Material temperature
    • ITR, IRD : interfacial traction and relative displacement
    • ELTIME: Element elapsed physical time after activation. This is a derived field computed from rtime - birthTime.
    • ECR, ESH, EAG: Creep strain, shrinkage strain, and aging strain
    • PEL: Element pressure
    • VOL: Element volumetric strain
