    3.3 hf2DStudio Remote Control Window and File

    3.3.1 Remote-only

    • Use these commands first to identify the running instance and confirm that remote control is working.
    hf2DStudio --remote list
hf2DStudio --remote target <set|show|clear> [id]
hf2DStudio --remote [--target <id>] status
hf2DStudio --remote [--target <id>] ping
hf2DStudio --remote [--target <id>] focus
hf2DStudio --remote [--target <id>] maximize
hf2DStudio --remote [--target <id>] minimize
hf2DStudio --remote [--target <id>] [--timeout-ms <ms>] script <file>
hf2DStudio --remote [--target <id>] script-save [file]
    • target: manage the local default target used when --target is omitted; see the target subsection below and Remote Control Basics

    3.3.1.1 list

    • Lists every running hf2DStudio instance.
    • Syntax: list
    • Validation: No positional arguments.
    • Behavior: Each line is uuid | pid | server | startedAt | file. The leading uuid can be pasted directly into target or --target <id>. When there is no running instance, a short message is printed and the command exits with success code 0. This command runs only in the local client and does not send an IPC request to any target.

    Example:

    hf2DStudio --remote list

    3.3.1.2 target

    • Stores the local default target used when --target is omitted.
    • Syntax: target set <id> target show target clear
    • Validation: set requires exactly one <id> argument, which must be a uuid or server name shown by list. show and clear take no additional arguments. --target cannot be combined with the target command.
    • Behavior: set resolves the id, writes it to the runtime directory, and prints the resulting JSON. show prints the stored default target as JSON and reports whether the instance is still alive. clear removes the stored default target. This command runs only in the local client.

    Example:

    hf2DStudio --remote target set 4e37d050-cda4-4a24-a885-4e0595554802
hf2DStudio --remote target show
hf2DStudio --remote target clear

    3.3.1.3 status

    • Returns the current status of the target instance as JSON.
    • Syntax: status
    • Validation: No positional arguments. A target instance must exist.
    • Behavior: Returns JSON with uuid, server name, current file path, start time, unsaved-change flag, and similar fields. Does not change section-model data and does not add any line to Remote Control History.

    Example:

    hf2DStudio --remote status

    3.3.1.4 ping

    • Checks the IPC connectivity to the target instance.
    • Syntax: ping
    • Validation: No positional arguments.
    • Behavior: Returns success when the connection and the round-trip response are healthy. Does not change section-model data and does not add any line to Remote Control History. Use it in automation scripts to quickly confirm that a target window is reachable.

    Example:

    hf2DStudio --remote ping

    3.3.1.5 Window State

    hf2DStudio --remote [--target <id>] focus
hf2DStudio --remote [--target <id>] maximize
hf2DStudio --remote [--target <id>] minimize
    • focus restores the window if needed, then raises and activates it.
    • maximize switches the target window to the maximized state, then raises and activates it.
    • minimize minimizes the target window.
    • These commands are remote-only UI helpers: they do not change section-model data and they do not append canonical command tails to Remote Control History.

    Example:

    hf2DStudio --remote maximize
hf2DStudio --remote focus
hf2DStudio --remote minimize

    3.3.1.6 script

    • Runs commands from a script file, one per line, against the target instance.
    • Syntax: script <file>
    • Validation: <file> must exist. Relative paths resolve against the CLI current working directory. Each line must carry only a command tail, without the hf2DStudio --remote prefix. Lines starting with # and empty lines are treated as comments and skipped.
    • Behavior: If any line fails, the command stops with SCRIPT_FAILED and reports the failing line number and the original error code and message. When a line is quit, the command returns the number of executed lines up to that point and the target window closes. --timeout-ms applies to the whole script request, not to individual lines, so give a long timeout for long scripts.

    Example:

    hf2DStudio --remote --timeout-ms 60000 script D:\Work\build-section.txt

    3.3.1.7 script-save

    • Saves the Remote Control History accumulated by the target instance into a script file.
    • Syntax: script-save [file]
    • Validation: Without [file], the default output path under <sessionRoot>/.hyfeast/ is used. With [file], that path is used; relative paths resolve against the CLI current working directory.
    • Behavior: Writes the default header comment (# One command tail per line (without "hf2DStudio --remote")) followed by the accumulated command tails as UTF-8 text with CRLF line endings. The saved lines match the history shown in the GUI Command panel. The saved file can be replayed directly with the script command.

    Example:

    hf2DStudio --remote script-save D:\Work\section-recipe.txt

    3.3.2 File

    • Use these commands to create, open, import into, save, or close section models from scripts or batch flows.
    hf2DStudio --remote [--target <id>] new [--discard-unsaved]
hf2DStudio --remote [--target <id>] open <file>
hf2DStudio --remote [--target <id>] import-dxf-geometry <file>
hf2DStudio --remote [--target <id>] save [file]
hf2DStudio --remote [--target <id>] quit [--discard-unsaved]
    • new:
    • without --discard-unsaved, follow the same save-confirmation flow as GUI File > New
    • Yes: save the current section first; if it has never been saved, open the Save As dialog
    • No: discard unsaved changes and create a new blank section model
    • Cancel: keep the current section open and fail with NEW_FAILED
    • open, quit:
    • if unsaved changes exist and the current file already has a path, auto-save first
    • if unsaved changes exist and there is no current file path, fail with SAVE_PATH_REQUIRED, except for an Untitled model whose only user change is the startup UnitSystem choice
    • import-dxf-geometry <file>:
    • imports supported DXF entities into the active section Geometry
    • uses the same hfStudio DXF importer path for LINE, LWPOLYLINE, POLYLINE, ARC, CIRCLE, ELLIPSE, and SPLINE, then converts the resulting Geometry Guide primitives to Line, Arc, Bezier, or Spline curves
    • ignores the final DXF/WCS z coordinate and uses only (x, y) as hf2DStudio Geometry coordinates
    • applies unit scaling only when both DXF $INSUNITS and the active section/global unit are valid; otherwise imports the numeric coordinates without scaling
    • fails when the active section already has a mesh; run make-mesh delete before importing
    • new --discard-unsaved:
    • discards unsaved changes immediately
    • does not show the GUI save confirmation dialog
    • use it only when the caller intentionally wants a non-interactive discard
    • quit --discard-unsaved:
    • discards unsaved changes without auto-save
    • does not show the GUI save confirmation dialog
    • closes the target window immediately after the remote request is accepted
    • save [file]:
    • without [file], save to current file
    • with [file], save there and update the current file path
