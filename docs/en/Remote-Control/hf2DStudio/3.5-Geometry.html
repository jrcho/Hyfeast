    3.5 hf2DStudio Remote Control Geometry

    3.5.1 Geometry

    hf2DStudio --remote [--target <id>] draw-point <yp,zp>
hf2DStudio --remote [--target <id>] draw-lines <yp,zp|P<point-id>> <yp,zp|P<point-id>> [<yp,zp|P<point-id>> ...]
hf2DStudio --remote [--target <id>] draw-arc <yp,zp> <yp,zp> <yp,zp>
hf2DStudio --remote [--target <id>] draw-bezier2 <yp,zp> <yp,zp> <yp,zp>
hf2DStudio --remote [--target <id>] draw-bezier3 <yp,zp> <yp,zp> <yp,zp> <yp,zp>
hf2DStudio --remote [--target <id>] draw-rbezier2 <yp,zp> <yp,zp> <yp,zp> --weights <w1>
hf2DStudio --remote [--target <id>] draw-rbezier3 <yp,zp> <yp,zp> <yp,zp> <yp,zp> --weights <w1,w2>
hf2DStudio --remote [--target <id>] draw-spline <yp,zp> <yp,zp> <yp,zp> [<yp,zp> ...]
hf2DStudio --remote [--target <id>] generate-circle <radius> <yp> <zp>
hf2DStudio --remote [--target <id>] generate-circular-points <radius> <yp> <zp> <start-angle-deg> <count>
hf2DStudio --remote [--target <id>] set-seed --curve-ids <id,id,...> --seed <integer>
hf2DStudio --remote [--target <id>] auto-seed --curve-ids <id,id,...>
hf2DStudio --remote [--target <id>] make-face --material <name> --curve-ids <id,id,...>
hf2DStudio --remote [--target <id>] make-rebar --material <name> --point-ids <id,id,...> --diameter <value> [--diameter-right <value>]
hf2DStudio --remote [--target <id>] move-point <point-id> <yp,zp> [--merge <on|off>]
hf2DStudio --remote [--target <id>] delete-point <id,id,...>
hf2DStudio --remote [--target <id>] delete-curve <id,id,...>
hf2DStudio --remote [--target <id>] delete-face <id,id,...>
hf2DStudio --remote [--target <id>] delete-rebar <id,id,...>
hf2DStudio --remote [--target <id>] select <point|curve|face|rebar> <id,id,...> [--mode <replace|add|remove|toggle>]
hf2DStudio --remote [--target <id>] delete-selection
hf2DStudio --remote [--target <id>] copy-selection --offset <yp,zp>
hf2DStudio --remote [--target <id>] merge-selected-points
hf2DStudio --remote [--target <id>] detach-selected-points
    • Geometry authoring commands require an editable geometry section.
    • If a mesh already exists, geometry authoring must not proceed until make-mesh delete is run.
    • Coordinate arguments use yp,zp.
    • Quote coordinate tokens when needed, especially for negative values such as "-25,10".
    • Coordinate-based draw commands resolve against the start-section geometry.
    • In draw-lines, a coordinate token creates a separate point, while P<point-id> connects the line to an existing point.
    • When a requested coordinate matches an existing point, the command still creates a new point instead of reusing the existing one.
    • New points are created with matching start/end coordinates, so taper sections start from the same geometry on both sides.
    • move-point targets one existing point id and updates every connected curve consistently.
    • move-point --merge on is the explicit remote-control path for connecting one moved point into existing topology.
    • move-point --merge on fails when either affected point is referenced by a face or rebar; delete the affected entity first.
    • Direct delete commands record the actual removed ids, so GUI Delete replay does not depend on prior selection reconstruction.
    • select does not require mesh deletion because it does not change geometry.
    • delete-selection requires editable geometry because it removes selected entities.
    • GUI geometry edits that delete an existing mesh record make-mesh delete before the geometry command. Remote Control commands fail until make-mesh delete is run explicitly.
    • copy-selection copies the current selection by an explicit offset and preserves duplicate coincident points as separate points.
    • GUI Move Selection replay is recorded as the resulting move-point commands, not as a separate move-selection command.
    • GUI Copy Selection replay records select reconstruction commands before copy-selection, because copy-selection operates on the current selection.
    • merge-selected-points merges only selected points that are already coincident and fails when a merge candidate is referenced by a face or rebar.
    • detach-selected-points duplicates selected shared points, but face-referenced split candidates fail the command; rebar-referenced points remain blocked.

    3.5.1.1 Draw Point

    Syntax:

    hf2DStudio --remote [--target <id>] draw-point <yp,zp>

    Arguments and behavior:

    • <yp,zp> is one geometry-point coordinate pair.
    • The command creates exactly one point.
    • The command creates a new point even if another point already exists at the same coordinates.
    • No curve, face, or rebar is created by this command.

    Example:

    hf2DStudio --remote draw-point "0,0"

    3.5.1.2 Draw Lines

    Syntax:

    hf2DStudio --remote [--target <id>] draw-lines <yp,zp|P<point-id>> <yp,zp|P<point-id>> [<yp,zp|P<point-id>> ...]

    Arguments and behavior:

    • Provide at least two point tokens.
    • A coordinate token <yp,zp> creates a separate point.
    • A point reference token P<point-id> reuses the existing point and connects the new line segment to that topology.
    • Each adjacent pair becomes one line segment.
    • Two points create one line segment, three points create two connected line segments, and so on.
    • Identical consecutive points are rejected.
    • Repeated non-consecutive points are allowed, so a polyline can return to a previous point.
    • Existing matching points are not reused; a new point is created for each requested coordinate.
    • GUI Remote History records P<point-id> when the drawing interaction chooses connect to existing point, and records coordinates when it chooses create separate point.

    Example:

    hf2DStudio --remote draw-lines "0,0" "300,0" "300,120"
hf2DStudio --remote draw-lines P1 "300,0" P2

    3.5.1.3 Draw Arc

    Syntax:

    hf2DStudio --remote [--target <id>] draw-arc <yp,zp> <yp,zp> <yp,zp>

    Arguments and behavior:

    • Provide exactly three points.
    • All three points must be distinct.
    • The three points must not be collinear.
    • The command creates one 2D arc using start, middle, and end points.
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-arc "0,0" "150,80" "300,0"

    3.5.1.4 Draw Bezier2

    Syntax:

    hf2DStudio --remote [--target <id>] draw-bezier2 <yp,zp> <yp,zp> <yp,zp>

    Arguments and behavior:

    • Provide exactly three control points.
    • All three points must be distinct.
    • The command creates one quadratic bezier curve.
    • The stored inner weight is w1 = 1.0.
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-bezier2 "0,0" "150,80" "300,0"

    3.5.1.5 Draw Bezier3

    Syntax:

    hf2DStudio --remote [--target <id>] draw-bezier3 <yp,zp> <yp,zp> <yp,zp> <yp,zp>

    Arguments and behavior:

    • Provide exactly four control points.
    • All four points must be distinct.
    • The command creates one cubic bezier curve.
    • The stored inner weights are w1 = 1.0 and w2 = 1.0.
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-bezier3 "0,0" "100,90" "220,90" "320,0"

    3.5.1.6 Draw Rational Bezier2

    Syntax:

    hf2DStudio --remote [--target <id>] draw-rbezier2 <yp,zp> <yp,zp> <yp,zp> --weights <w1>

    Arguments and behavior:

    • Provide exactly three control points and one inner weight.
    • All three points must be distinct.
    • The command creates one rational quadratic bezier curve.
    • --weights <w1> defines the inner control-point weight.
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-rbezier2 "0,0" "150,80" "300,0" --weights "0.70710678"

    3.5.1.7 Draw Rational Bezier3

    Syntax:

    hf2DStudio --remote [--target <id>] draw-rbezier3 <yp,zp> <yp,zp> <yp,zp> <yp,zp> --weights <w1,w2>

    Arguments and behavior:

    • Provide exactly four control points and two inner weights.
    • All four points must be distinct.
    • The command creates one rational cubic bezier curve.
    • --weights <w1,w2> defines the two inner control-point weights.
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-rbezier3 "0,0" "100,90" "220,90" "320,0" --weights "0.85,0.85"

    3.5.1.8 Draw Spline

    Syntax:

    hf2DStudio --remote [--target <id>] draw-spline <yp,zp> <yp,zp> <yp,zp> [<yp,zp> ...]

    Arguments and behavior:

    • Provide at least three control points.
    • The command creates one spline curve through the requested points.
    • Repeated coordinates are rejected except for one closing case:
    • if the last point matches the first point, the spline is created as a closed spline
    • The curve seed is initialized from the current section-model default curve seed.
    • Existing matching points are not reused; a new point is created for each requested coordinate.

    Example:

    hf2DStudio --remote draw-spline "0,0" "120,80" "240,40" "240,-40" "0,0"

    3.5.1.9 Move Point

    Syntax:

    hf2DStudio --remote [--target <id>] move-point <point-id> <yp,zp> [--merge <on|off>]

    Arguments and behavior:

    • <point-id> is one existing geometry point id.
    • <yp,zp> is the destination coordinate pair for that point.
    • The command updates every connected curve after the point move.
    • The default is no merge.
    • --merge on keeps the moved point id and merges any duplicate destination point into it.
    • --merge on fails when either affected point is referenced by a face or rebar; delete the affected entity first.
    • --merge off leaves other points untouched, even if another point already exists at the destination.
    • The command succeeds as a no-op when the destination already matches the current point coordinates.

    Example:

    hf2DStudio --remote move-point 12 "250,100" --merge off

    3.5.1.10 Make Face

    Syntax:

    hf2DStudio --remote [--target <id>] make-face --material <name> --curve-ids <id,id,...>

    Arguments and behavior:

    • --material <name> selects one existing section material.
    • --curve-ids <id,id,...> is a non-empty comma-separated curve-id list.
    • If the requested curves already define one exact face, including hole loops, the command creates that face as-is.
    • Otherwise the command resolves bounded cells from the requested curves and creates one face for each new cell it can determine.
    • Shared boundary curves split neighboring cells into separate faces.
    • Extra curves that do not bound any cell are ignored.
    • Already-existing faces with the same resolved curve set are skipped.
    • The command fails only when it cannot resolve any new face from the requested curves.
    • Success JSON always returns faceIds; faceId is also returned when exactly one face is created.

    Example:

    hf2DStudio --remote make-face --material CONC --curve-ids "1,2,3,4"

    3.5.1.11 Delete Point

    Syntax:

    hf2DStudio --remote [--target <id>] delete-point <id,id,...>

    Arguments and behavior:

    • <id,id,...> is a comma-separated point-id list.
    • Points are deleted only when they are not referenced by any remaining curve or rebar.
    • Safe ids are deleted; blocked ids are reported in the JSON result.

    Example:

    hf2DStudio --remote delete-point "8,12"

    3.5.1.12 Delete Curve

    Syntax:

    hf2DStudio --remote [--target <id>] delete-curve <id,id,...>

    Arguments and behavior:

    • <id,id,...> is a comma-separated curve-id list.
    • Curves are deleted only when they are not referenced by any remaining face.
    • Safe ids are deleted; blocked ids are reported in the JSON result.

    Example:

    hf2DStudio --remote delete-curve "3,7"

    3.5.1.13 Delete Face

    Syntax:

    hf2DStudio --remote [--target <id>] delete-face <id,id,...>

    Arguments and behavior:

    • <id,id,...> is a comma-separated face-id list.
    • Every requested face id is deleted directly.

    Example:

    hf2DStudio --remote delete-face "4,5"

    3.5.1.14 Delete Rebar

    Syntax:

    hf2DStudio --remote [--target <id>] delete-rebar <id,id,...>

    Arguments and behavior:

    • <id,id,...> is a comma-separated rebar-id list.
    • Every requested rebar id is deleted directly.

    Example:

    hf2DStudio --remote delete-rebar "2,9"

    3.5.1.15 Select

    Syntax:

    hf2DStudio --remote [--target <id>] select <point|curve|face|rebar> <id,id,...> [--mode <replace|add|remove|toggle>]

    Arguments and behavior:

    • <point|curve|face|rebar> chooses one geometry entity type.
    • <id,id,...> is a comma-separated positive-id list.
    • --mode replace rebuilds the selection from the requested ids.
    • --mode add, remove, and toggle update the current selection state in place.
    • The command changes selection only; it does not create or delete geometry.

    Example:

    hf2DStudio --remote select curve "3,7,9" --mode add

    3.5.1.16 Delete Selection

    Syntax:

    hf2DStudio --remote [--target <id>] delete-selection

    Arguments and behavior:

    • The command deletes the currently selected removable entities in the active section.
    • Faces and rebars in the selection are deleted immediately.
    • Curves referenced by faces are kept and remain selected.
    • Points referenced by curves or rebars are kept and remain selected.
    • If nothing removable is selected, the command succeeds as a no-op.

    Example:

    hf2DStudio --remote select face "4"
hf2DStudio --remote delete-selection

    3.5.1.17 Merge Selected Points

    Syntax:

    hf2DStudio --remote [--target <id>] merge-selected-points

    Arguments and behavior:

    • The command takes no positional arguments.
    • It inspects the current selected-point set in the active section.
    • Selected points that already share the same coordinates are merged into one shared topology point per coordinate group.
    • The surviving point keeps its existing id. Removed duplicate ids are reported in the result JSON.
    • If a selected duplicate merge candidate is referenced by a face or rebar, the command fails. Delete the affected entity first.
    • This command is an explicit topology operation. Use move-point --merge on when you want to connect by moving one point onto another location intentionally.

    Example:

    hf2DStudio --remote select point "12,18"
hf2DStudio --remote merge-selected-points

    3.5.1.18 Detach Selected Points

    Syntax:

    hf2DStudio --remote [--target <id>] detach-selected-points

    Arguments and behavior:

    • The command takes no positional arguments.
    • It inspects the current selected-point set in the active section.
    • Each selected point shared by multiple curves is split into independent coincident points so the attached curves no longer share one topology point.
    • New duplicate point ids are reported in the result JSON.
    • If a selected split candidate is referenced by a face, the command fails. Delete the affected face first.
    • Points still referenced by rebars are blocked and left unchanged.

    Example:

    hf2DStudio --remote select point "21"
hf2DStudio --remote detach-selected-points

    3.5.1.19 Set Seed

    Syntax:

    hf2DStudio --remote [--target <id>] set-seed --curve-ids <id,id,...> --seed <integer>

    Arguments and behavior:

    • --curve-ids <id,id,...> is a comma-separated curve-id list.
    • --seed <integer> assigns one explicit seed count to every requested curve.
    • The seed must be a positive integer.
    • Lines accept 1 or greater. Arcs, bezier curves, and splines clamp to their built-in minimum seed when needed.
    • The command requires editable geometry and fails when any requested curve id is missing.
    • This command only assigns manual seeds. It does not run the TFI interval correction used by auto-seed.

    Example:

    hf2DStudio --remote set-seed --curve-ids "2" --seed 3

    3.5.1.20 Auto Seed

    Syntax:

    hf2DStudio --remote [--target <id>] auto-seed --curve-ids <id,id,...>

    Arguments and behavior:

    • --curve-ids <id,id,...> is a comma-separated curve-id list.
    • Cannot be combined with --seed.
    • Recomputes rough seed counts from the smallest max-H value found across the requested curves.
    • After the rough pass, tries conservative TFI interval correction on hole-free single-outer-loop faces whose outer-loop curves are all included in this --curve-ids set.
    • Correction only increases seeds on deficient sides. The per-face budget is min(4, max(1, ceil(totalSideIntervals * 0.20))); if the required correction is larger or ambiguous, the rough seeds are kept.
    • If the face has Quad Mesh Corner Hints, the hint plan is used before automatic corner candidates.
    • The command requires editable geometry and fails when any requested curve id is missing.
    • Produces the same result as the Auto Seed button in the GUI.
    • The success response's intervalCorrections value is the number of stored seed increments applied by the correction pass.

    Example:

    hf2DStudio --remote auto-seed --curve-ids "1,2,3,4"

    3.5.1.21 Generate Circle

    Syntax:

    hf2DStudio --remote [--target <id>] generate-circle <radius> <yp> <zp>

    Arguments and behavior:

    • <radius> must be a positive finite number.
    • <yp>, <zp> give the section coordinates of the center.
    • Creates one closed circle composed of four rational quadratic bezier segments.
    • Each segment seed is initialized to the current default curve seed of the section model.
    • The command requires editable geometry.

    Example:

    hf2DStudio --remote generate-circle 50 0 0

    3.5.1.22 Generate Circular Points

    Syntax:

    hf2DStudio --remote [--target <id>] generate-circular-points <radius> <yp> <zp> <start-angle-deg> <count>

    Arguments and behavior:

    • <radius> must be a positive finite number.
    • <yp>, <zp> give the section coordinates of the center.
    • <start-angle-deg> is the angle of the first point; positive angles rotate from the +y axis toward the +z axis.
    • <count> is a positive integer that specifies how many points to create.
    • Creates <count> evenly spaced points on the circle of radius <radius>.
    • Creates points only; no curves are created. Useful for assembling rebar groups.
    • The command requires editable geometry.

    Example:

    hf2DStudio --remote generate-circular-points 60 0 0 0 8

    3.5.1.23 Copy Selection

    Syntax:

    hf2DStudio --remote [--target <id>] copy-selection --offset <yp,zp>

    Arguments and behavior:

    • --offset <yp,zp> is the copy offset in section coordinates.
    • The command inspects the current geometry selection in the active section.
    • Selected points, curves, faces, and rebars are copied.
    • Curves, faces, and rebars copy their referenced points as independent new points, even when the copied points become coincident with existing points.
    • Face materials are copied, while face and rebar colors are assigned as newly created entities.
    • Rebar material and diameter settings are copied.

    Example:

    hf2DStudio --remote select curve "1,2"
hf2DStudio --remote copy-selection --offset "100,0"
