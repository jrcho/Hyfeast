    3.7 hf2DStudio Remote Control Operation and Analysis

    3.7.1 Operation

    hf2DStudio --remote [--target <id>] make-mesh [build|delete|toggle]
hf2DStudio --remote [--target <id>] make-mesh --mode <build|delete|toggle>
hf2DStudio --remote [--target <id>] compute-section-constants [compute|invalidate|toggle]
hf2DStudio --remote [--target <id>] compute-section-constants --mode <compute|invalidate|toggle>
hf2DStudio --remote [--target <id>] renumber
hf2DStudio --remote [--target <id>] move <top-left|top-middle|top-right|middle-left|middle-middle|middle-right|bottom-left|bottom-middle|bottom-right|centroid|shear-center|offset> [--offset <yp,zp>]
hf2DStudio --remote [--target <id>] rotate <angle-deg>
hf2DStudio --remote [--target <id>] export-section [--name <name>]
hf2DStudio --remote [--target <id>] export-guide-geometry [--side <left|right>] [--ref-cs <name>] [--name <name>]
hf2DStudio --remote [--target <id>] export-curve-mesh [--side <left|right>] [--node-id-offset <id>] [--element-id-offset <id>] [--ref-cs <name>]
hf2DStudio --remote [--target <id>] export-domain-mesh [--side <left|right>] [--node-id-offset <id>] [--element-id-offset <id>] [--ref-cs <name>]
    • move offset requires --offset <yp,zp>.
    • make-mesh build builds the mesh and computes section constants together.
    • All export commands copy the exported text to the clipboard and also return the same text in the result JSON payload.
    • If the section model has a global *Environment, TYPE=UnitSystem, every export writes that UnitSystem block at the beginning of the exported text.

    3.7.1.1 export-section

    • Exports the active section definition as *Section, TYPE=Beam input text.
    • Options: --name <name> overrides the exported section name. When omitted, the current section name is used.
    • Validation: Requires an active section in the target hf2DStudio. Requires an existing section mesh.
    • Behavior: Copies the exported beam-section text to the clipboard. Returns the same text in the remote result JSON. The output includes the section definition and the section data needed to recreate the section input block. If the current section mesh contains quadratic cells, the exported *Cell, TYPE=Mesh block keeps the original T6/Q8 connectivity instead of silently downgrading it to T3/Q4.

    Example:

    hf2DStudio --remote export-section

    3.7.1.2 export-guide-geometry

    • Exports the active section geometry as *Geometry, TYPE=Guide text.
    • Options: --side <left|right> selects the side-dependent geometry to export when the section uses taper-aware data. --ref-cs <name> appends Ref=<name> to the exported *Geometry keyword line. --name <name> overrides the exported geometry name. When omitted, the current section name is used.
    • Validation: Requires an active section in the target hf2DStudio. Requires active geometry with curve data.
    • Behavior: Copies the generated guide geometry text to the clipboard. Returns the same text in the remote result JSON. Guide points are exported on the Z=0 plane using section yp/zp as x/y. The optional reference coordinate system name is written only on the exported keyword line. The output uses the Guide primitive form that matches the current section geometry.

    Example:

    hf2DStudio --remote export-guide-geometry --side left --ref-cs CS-1 --name Guide-1

    3.7.1.3 export-curve-mesh

    • Exports the active section curves as a 1D curve mesh.
    • Options: --side <left|right> selects the side-dependent curve set when the geometry is side-aware. --node-id-offset <id> shifts generated node IDs by the specified offset. --element-id-offset <id> shifts generated element IDs by the specified offset. --ref-cs <name> assigns the reference coordinate system name used in the exported node block.
    • Validation: Requires an active section in the target hf2DStudio. Requires active geometry with curve data.
    • Behavior: Copies the exported curve mesh text to the clipboard. Returns the same text in the remote result JSON. The output follows the current curve-mesh export format used by the GUI. This is a seed-point-based 1D curve-mesh export. It uses the geometry curve sampling and writes the current 1D FE format used by the GUI, independent of the domain-mesh order.

    Example:

    hf2DStudio --remote export-curve-mesh --side right --node-id-offset 1000 --element-id-offset 2000 --ref-cs CS-1

    3.7.1.4 export-domain-mesh

    • Exports the active section domain mesh as 2D FE input text.
    • Options: --side <left|right> selects the side-dependent domain when the section uses taper-aware data. --node-id-offset <id> shifts generated node IDs by the specified offset. --element-id-offset <id> shifts generated element IDs by the specified offset. --ref-cs <name> assigns the reference coordinate system name used in the exported text.
    • Validation: Requires an active section in the target hf2DStudio. Requires an existing section mesh.
    • Behavior: Copies the exported domain mesh text to the clipboard. Returns the same text in the remote result JSON. The export always follows the mesh-only domain-mesh format used by the GUI. The command preserves the current domain-mesh order. Linear meshes export CPS3/CPS4, and quadratic meshes export CPS6/CPS8.

    Example:

    hf2DStudio --remote export-domain-mesh --side left --node-id-offset 1000 --element-id-offset 2000 --ref-cs CS-1

    3.7.1.5 make-mesh

    • Builds, deletes, or toggles the active section mesh.
    • Validation: build requires section geometry. delete removes the current mesh only when one exists.
    • Behavior: build creates the mesh and then computes section constants immediately. In other words, centroid, shear-center, and other derived section constants are prepared in the same step. The remote command does not take a linear/quadratic option. It uses the mesh-order state already held by the current hf2DStudio session. build uses the currently stored curve seeds and Quad Mesh Corner Hints; it does not rerun auto-seed interval correction or mutate seeds. If the TFI interval condition is not met, or if the candidate is not uniquely safe, that face continues through the Netgen fallback path. If a mesh already exists, build returns success without replacing it. Delete the current mesh first if you want to rebuild with a different order. In the GUI, the equivalent operations are Operation > Make Linear Mesh, Operation > Make Quadratic Mesh, and Operation > Delete Mesh.

    Example:

    hf2DStudio --remote make-mesh build

    3.7.1.6 compute-section-constants

    • Computes, invalidates, or toggles section constants for the active section mesh.
    • Validation: Requires an existing mesh.
    • Behavior: Use this command when you want to recompute or invalidate section constants for an existing mesh. make-mesh build already computes section constants by default.

    3.7.1.7 renumber

    • Renumbers all geometry entities of the active section.
    • Syntax: renumber
    • Validation: No positional arguments. An active section must exist in the target hf2DStudio.
    • Behavior: Points, curves, faces, and rebars each get fresh ids starting from 1. All externally cached ids become invalid; the next step must query ids again. Produces the same result as GUI Operation > Renumber and is recorded into Remote Control History with the same command form.

    Example:

    hf2DStudio --remote renumber

    3.7.1.8 move

    • Translates the whole active section by an anchor rule or an explicit offset.
    • Syntax: move <anchor> [--offset <yp,zp>]
    • Validation: <anchor> must be one of: top-left, top-middle, top-right, middle-left, middle-middle, middle-right, bottom-left, bottom-middle, bottom-right, centroid, shear-center, offset. --offset <yp,zp> is allowed only with the offset anchor, in which case it is required. Supplying --offset with any other anchor fails.
    • Behavior: The nine directional anchors move the axis-aligned bounding box so that the chosen anchor sits at the origin (0,0). centroid moves the current section-constants centroid to the origin; shear-center moves the shear center. offset translates the whole geometry by <yp,zp> without changing the anchor point itself. Matches the GUI Operation > Move actions and is recorded into Remote Control History with the same command form.

    Example:

    hf2DStudio --remote move centroid
hf2DStudio --remote move offset --offset "10,5"

    3.7.1.9 rotate

    • Rotates the whole active section by the given angle.
    • Syntax: rotate <angle-deg>
    • Validation: The angle must be a single finite number. An active section must exist in the target hf2DStudio.
    • Behavior: Rotates the geometry about the current origin (yp=0, zp=0); positive angles rotate from the +y axis toward the +z axis. After rotating you can follow up with move centroid or move shear-center to realign the anchor if needed. Matches the GUI Operation > Rotate action and is recorded into Remote Control History with the same command form.

    Example:

    hf2DStudio --remote rotate 30
hf2DStudio --remote rotate -90

    3.7.2 Analysis

    hf2DStudio --remote [--target <id>] run-analysis
hf2DStudio --remote [--target <id>] unlock-model
    • Requires an existing saved file path.
    • If unsaved changes exist, auto-save is attempted before analysis starts.
    • No extra CLI options are accepted. The remote command uses the same analyzer launch path as the GUI action.
    • unlock-model mirrors the GUI Unlock model action and deletes the current section-analysis result so editing returns to preprocessing mode.
    • unlock-model is available only when a result file exists or analysis results are currently loaded.

    3.7.2.1 run-analysis

    • Starts section analysis in the same way as the GUI analysis action.
    • Validation: Requires a saved current file path. Fails if analysis is already running.
    • Behavior: If unsaved changes exist, the current file is saved first. Existing .xlsx result output for the current section file is removed before the new run starts.

    Example:

    hf2DStudio --remote run-analysis

    3.7.2.2 unlock-model

    • Deletes the current section-analysis result and returns the model to editable preprocessing mode.
    • Validation: Takes no positional arguments. Fails while analysis is running. Fails when no saved or loaded result exists.
    • Behavior: Removes the current .xlsx analysis-result file when present. Clears loaded analysis result data from the active session even if only in-memory results remain. GUI Unlock model also appends the same canonical unlock-model tail to Remote Control History after success.

    Example:

    hf2DStudio --remote unlock-model
