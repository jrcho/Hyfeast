    4 Building Plugins

    A plugin is a 64-bit Windows DLL file. Building your source file (C or Fortran) with a compiler produces the DLL, and the path of that DLL goes on the first dataline of *Material, Type=User.

    4.1 Preparation

    Required programs
    Way Required programs
    C, C++ Visual Studio 2019 or later with "Desktop development with C++" installed (recommended), or MinGW-w64 GCC targeting Windows x64
    Native Fortran, Abaqus UMAT Intel oneAPI Fortran compiler (ifx) and a compatible Visual Studio 2019 or later with the same C++ components installed

    C/C++ plugins can also be built with GCC from MinGW-w64. GCC 8 or later is recommended; use a toolchain that produces Windows x64 DLLs. Visual Studio 2019 or later is recommended because the main build procedure in this guide and the example build.bat use Visual Studio.

    If Visual Studio 2019 or later is already installed with "Desktop development with C++", use that installation. If the C++ components are missing, add them through "Modify" in the Visual Studio Installer. This workload includes the C/C++ compiler and Windows SDK (Microsoft installation guide).

    For Fortran, also install the Intel oneAPI Fortran compiler. Check the Intel compatibility table to confirm that your ifx version supports the installed Visual Studio version.

    If Visual Studio is absent and you only need command-line builds, you can select "Desktop development with C++" in the separate Build Tools installer. Include the x64 build tools and Windows SDK; for Fortran, select a version compatible with your ifx (Build Tools installation guide).

    Folders used in the examples of this chapter

    The example distribution folder in this chapter is D:\Apps\Hyfeast-v1.0.0. Executables are in Bin, and user material examples are in Examples\UMAT. Keep the source and DLL of your own material in the work folder D:\MyUMAT. Replace distribution folder paths in the commands below with your actual extraction location and version name, and work folder paths with your own working location.

    Folder Example path Content
    Distribution folder D:\Apps\Hyfeast-v1.0.0 Folder containing Bin, Examples, and HyfeastCmd.bat after extracting the ZIP
    Development kit folder D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial Header, Fortran template, Abaqus bridge, build_umat.cmd, example sources (Section 1.3)
    Work folder D:\MyUMAT Folder that holds your material source and where the DLL is built

    If a path contains spaces (e.g. D:\My Work\UMAT), enclose it in double quotes in the commands.

    Opening a command window

    Building is done in a command window.

    1. From the Windows Start menu, open the x64 developer command prompt for your installed Visual Studio or Build Tools. Its name depends on the installed version; x64 Native Tools Command Prompt for VS 2022 is one example. This window sets up the C compiler (cl), linker and Windows SDK for x64. You can also build Fortran in this window. When installation paths can be found automatically, build_umat.cmd can also run from an ordinary command prompt (cmd) (Section 4.5).
    2. Move to the work folder.
    cd /d D:\MyUMAT

    Type all following commands in this window.

    4.2 C plugin

    1. Copy the example source D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\NativeElasticC\hfUmatElasticC.c to the work folder and rename it (e.g. D:\MyUMAT\mymat.c).
    2. Open the file and change the body of the function hf_umat_v1 to your material model. Keep the argument list and the function hf_umat_abi_version as they are (Chapter 3).
    #include "hfUserMaterialAPI.h"

HF_UMAT_EXPORT void hf_umat_v1(double* stress, double* statev, double* ddsdde, /* ... 37 arguments ... */
                               const hf_int* jstep, const hf_int* kinc)
{
  const int n = *ntens;
  /* fill ddsdde[i + j*n] and update stress[i], statev[k] */
}

HF_UMAT_EXPORT hf_int hf_umat_abi_version(void) { return HF_UMAT_ABI_VERSION; }
    1. In the x64 developer command prompt opened in Section 4.1, type:
    cd /d D:\MyUMAT
cl /nologo /O2 /LD /I"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\include" mymat.c /Fe"mymat.dll"
    Option Meaning
    /LD Builds a DLL
    /O2 Optimizes
    /I"...\include" Folder that contains the header hfUserMaterialAPI.h
    /Fe"mymat.dll" Name of the DLL to build
    1. mymat.dll appears in the work folder. The files created with it (mymat.obj, mymat.lib, mymat.exp) are not needed for the analysis.

    C++ may also be used. With the header included, the functions are still exported under their C names. Do not let exceptions leave the functions.

    With MinGW-w64 GCC, build as follows in a command window where gcc is available. -shared creates the DLL, and -static-libgcc links the GCC support library statically.

    cd /d D:\MyUMAT
gcc -std=c99 -O2 -shared -static-libgcc -I"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\include" mymat.c -o mymat.dll

    Build C++ sources with g++. For C++17, specify -std=c++17; add -static-libstdc++ to link the C++ standard library statically as well. If the plugin depends on other DLLs, distribute them with it.

    4.3 Native Fortran plugin

    1. Copy the template D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\fortran\hf_umat_template.f90 to the work folder and rename it (e.g. D:\MyUMAT\mymat.f90). A complete example is D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\NativeElasticFortran\hfUmatElasticF.f90.
    2. Keep the declarations and write the material model where ! ... user material law ... stands. Indices start at 1 as in Abaqus.
    3. In the command window, type:
    cd /d D:\MyUMAT
"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native mymat.dll mymat.f90

    If there are several source files, list them after the first one.

    "D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native mymat.dll mymat.f90 tools.f90
    1. The build succeeded when build_umat: created D:\MyUMAT\mymat.dll appears at the end.

    4.4 Abaqus UMAT

    A SUBROUTINE UMAT source used in Abaqus is built without changes.

    1. Put the UMAT source (e.g. umat.for) in the work folder D:\MyUMAT. Keep INCLUDE 'ABA_PARAM.INC' as it is.
    2. In the command window, type:
    cd /d D:\MyUMAT
"D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" abaqus umat.dll umat.for
    1. The build succeeded when build_umat: created D:\MyUMAT\umat.dll appears at the end.

    With abaqus, build_umat.cmd automatically builds the following two files together. You do not need to copy them.

    • D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\abaqus\hfAbaqusUmatBridge.f90: the bridge between Hyfeast and the original UMAT. It exports hf_umat_v1 and hf_umat_abi_version, converts CMNAME into a blank-padded CHARACTER*80 and calls the original UMAT.
    • D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\abaqus\ABA_PARAM.INC: the file found by INCLUDE 'ABA_PARAM.INC' in the UMAT (IMPLICIT REAL*8(A-H,O-Z)).

    Conditions:

    • The UMAT must be self-contained. Calls to Abaqus utility routines (SINV, SPRINC, ROTSIG, XIT, ...) fail at the last build step.
    • Put only one material (one hf_umat_v1) in a DLL. Do not put a Native Fortran material and an Abaqus UMAT into the same DLL.
    • Old UMATs that declare a scalar KSTEP still work.
    • Examples: D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\AbaqusElasticUMAT\umat_elastic.for (elastic), D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\examples\AbaqusPlasticUMAT\umat_vonmises.for (von Mises plasticity).

    4.5 What build_umat.cmd does

    "D:\Apps\Hyfeast-v1.0.0\Examples\UMAT\UserMaterial\build_umat.cmd" native|abaqus DLLname sourcefile [sourcefile ...]
    • Finding the compiler: If the Intel Fortran environment is not set up, it runs the environment setup of the installed oneAPI automatically (the path in the IFX_COMPILER26 environment variable if it exists, otherwise C:\Program Files (x86)\Intel\oneAPI\setvars.bat). If the Microsoft link tool is not found either, it finds and sets up the installed Visual Studio. An ordinary command prompt works when the installation can be found automatically. If automatic detection fails, set up the Intel oneAPI environment in the x64 developer command prompt for your installed Visual Studio or Build Tools, then run the script.
    • Compiler options: /O2 /recursive /threads /libs:static /dll. /recursive puts local arrays on the stack so that several integration points can be computed at the same time safely. /libs:static puts the libraries needed to run Fortran into the DLL, so only the resulting DLL needs to be moved.
    • Created files: mymat.dll (the file used by the analysis), mymat.lib, mymat.exp and the folder mymat.dll.build (intermediate files). Only mymat.dll is needed for the analysis.

    4.6 Using the DLL

    Write the DLL path on the first dataline of *Material, Type=User. An absolute path is the most reliable.

    *Material, Type=User, Name=myMaterial
 D:\MyUMAT\mymat.dll, NState=5, NProps=4
 200000., 0.3, 250., 2000.

    If the DLL is in the same folder as the input file (.inp), the file name alone is enough (mymat.dll). When moving to another computer, move only the DLL file along with the input.

    4.7 Checks and troubleshooting

    First check the material-point response (S, E, DSDE) with *TestMaterial, then run element analyses (Section 5.5).

    Messages while building:

    Message Cause and remedy
    build_umat: ifx not found. Install Intel oneAPI Fortran or set IFX_COMPILER26. Intel Fortran is not installed or was not found. Install the Intel oneAPI Fortran compiler.
    build_umat: MSVC link.exe not found. Install Visual Studio C++ build tools. The MSVC linker is missing or its environment is not set up. Install the MSVC build tools and Windows SDK compatible with your ifx, then run in that installation's x64 developer command prompt.
    'cl' is not recognized as an internal or external command The C compiler is missing or its environment is not set up. Install the MSVC build tools and Windows SDK, then run in that installation's x64 developer command prompt.
    Link error LNK2019 (unresolved external symbol) naming SINV, XIT, ... The UMAT calls Abaqus utility routines. They are not supported; replace the calls with your own code.
    build_umat: compilation failed. The source has a syntax error. Check the line numbers in the compiler messages shown above.

    Messages in the analysis log (.log):

    Log message Cause and remedy
    User material "name": cannot load path ... (code 126) The DLL, or another DLL it needs, was not found. Check the path on the first dataline. Put other required DLLs in the folder of the plugin DLL.
    hf_umat_abi_version is not exported by ... The function is not exported. Check that the HF_UMAT_EXPORT (C) or !DEC$ ATTRIBUTES DLLEXPORT (Fortran) line is there.
    symbol is not exported by ... hf_umat_v1 (or the symbol of the first dataline) is not exported or has another name.
    ABI version n of ... does not match 1 hf_umat_abi_version does not return 1.
    Invalid syntax (first dataline) Unknown key, a key given twice, a key without value (NState=), or library missing.
    Invalid value in user material Negative NState, NProps below 1, negative Density, or Unsymm/Thread other than Yes or No.
    Invalid PROPS value in user material A non-numeric or empty value from the second dataline on.
    NProps is n but m PROPS values are given The number of PROPS values differs from NProps.
    User material name must be at most 80 characters The material name is longer than 80 characters.
    PROPS cannot be converted between unit systems The user material was read from a file with a UnitSystem different from the model. Convert PROPS to the model unit system and put them in a file of the same unit system.
    User material "name" returned non-finite values The plugin returned NaN or infinity. The increment is reduced and retried; if it persists the analysis stops.
    Invalid cell material A user material was given as a beam section cell material (uniaxial condition not supported).
    Laminar condition not supported, Uniaxial condition not supported, ... The user material was assigned to an unsupported condition (composite plates, uniaxial elements, interface elements).
