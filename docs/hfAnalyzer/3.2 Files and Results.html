    3.2 Files and Results

    hfAnalyzer 실행 전후에 마주치는 입력 파일과 결과 파일을 정리한다.

    3.2.1 입력 파일 .inp

    hfAnalyzer가 읽는 중심 입력 파일이다.

    • 모델, 하중, 재료, section, function, 해석 step 정의가 들어 있다
    • *로 시작하는 command block 구조를 따른다

    block 자체의 문법 규칙은 Command Reference에서 본다.

    3.2.2 실행 직후 확인하는 텍스트 파일

    3.2.2.1 .log

    실행 로그 파일이다.

    • 실행이 어디까지 진행됐는지
    • warning이나 error가 있었는지
    • solver가 어떤 흐름으로 움직였는지

    3.2.2.2 .chk

    재구성된 입력 파일이다.

    • 실제로 solver가 받아들인 모델 구성을 다시 확인할 때 본다
    • *Include로 펼쳐진 최종 입력 형태를 그대로 확인할 수 있다
    • include나 parameter 치환 결과를 검토할 때 본다
    • global *Environment, TYPE=UnitSystem이 중복되지 않았는지 점검할 때도 쓴다

    3.2.2.3 .prn

    텍스트 형식의 출력 결과 파일이다. 일반적으로 .inp와 같은 폴더에 생성된다.

    • 실행 상태와 종료 여부를 확인한다
    • warning과 error 메시지 — grep -i "error\|warning" 같은 빠른 검색을 쓴다
    • step별 결과가 기대와 맞는지 본다
    • 어디까지 진행됐는지 기본 정보가 들어 있다

    step별 결과 정의 문법은 Step Result에서 본다.

    3.2.3 결과 데이터베이스 .hdb

    후처리에 사용하는 결과 데이터베이스이다.

    • 그래픽 기반 결과 검토가 필요하면 hfStudio에서 연다
    • step, frame, contour, history 검토의 기반이 된다

    핵심 구조는 HDB File Structure에서 본다.

    3.2.3.1 .hdb 형식별 차이

    hfAnalyzer는 결과 데이터베이스를 여러 형식으로 만들 수 있다.

    기본 HDF5 형식:

    frame.hdb
frame.log
frame.chk
frame-step1.rst
frame-step2.rst

    text 형식:

    frame.text.hdb
frame.text.hdb.info
frame.text.hdb.inp
frame.log
frame.chk
frame-step1.rst
frame-step2.rst

    binary 형식:

    frame.bin.hdb
frame.log
frame.chk
frame-step1.rst
frame-step2.rst

    3.2.4 restart 파일 -step*.rst

    step restart 파일이다.

    • step 단위 재시작이나 중간 결과 흐름과 관련된다
    • 해석 절차가 길거나 step이 여러 개인 경우 존재를 확인하게 된다

    3.2.5 hfStudio에서 결과 검토

    다음 목적이면 hfStudio로 넘어간다.

    • contour 검토
    • deformed shape 확인
    • step/frame 탐색
    • 장면 기반 결과 검토

    자세한 내용은 hfStudio Help.
